## 交付

`0011_rls_identity` 对 `users`、`roles`、`user_role_assignments`、`tenant_user_memberships`、`auth_sessions` 启用并强制 RLS，按业务与认证角色分列授权。业务账号不能 SELECT 密码哈希；认证账号只能读取登录所需的身份列，不能读取联系方式、成员编号或论文表。认证查询使用显式投影；业务密码读取仅在登录路径显式加载。

学校账号新建用户时记录创建者及创建时学校，角色分配和成员写入需匹配该学校、角色和组织。直接 SQL 回归先复现了学校账号借已有外校用户 ID 注入成员关系，以及创建者调校后仍读旧校用户的问题；增加创建归属约束后均被拒绝。系统管理员仅能读取和维护 STAFF membership；停校时按角色分配枚举账号，以保持全员会话撤销。学生/导师仍可锁本人 membership，但写入触发器拒绝其修改。保留 User→AuthSession 锁顺序。

`provisioned_by` 与 `provisioned_tenant_id` 两个字段置于 `0010_auth_version`：验收夹具在升级 `0011` 前用当前 ORM 写种子，必须先有列。`0011→0010→0011` 与 `0010` 自身迁移测试已通过；最终 head 尚不是可部署版本，后续 23 张表尚待策略。
