日期：2026-09-24。分支 `codex/slice-7a1-file-integrity`，HEAD `39a8962c489163018a49ef5058171925c4faaa9d`；T01–R09 与本项仍在原工作树，未提交、推送、合并或部署。测试只使用本机 `127.0.0.1:5433/paper_review_test` 的唯一 `test_*` schema 和 `rls_*` 临时 PostgreSQL 角色；未迁移开发业务库，未修改原始材料。环境为 Python 3.12.7、PostgreSQL 16-alpine。

## 交付与边界

- `Settings` 增加迁移、业务、认证三种数据库 URL；声明 `APP_ENV=production` 时缺任一 URL 或三者非不同登录名均启动失败。Alembic 用迁移 URL，默认 HTTP engine 用业务 URL。开发环境保留旧 `DATABASE_URL` 回退，供尚未迁入 RLS 的旧测试使用。
- 测试夹具在独立测试库创建唯一 owner、business、auth 三个真实 LOGIN 角色，以 owner 建 schema 和迁移，以普通 business/auth 会话检查权限。业务角色不是 superuser、无 `BYPASSRLS`、非表 owner、无 owner/auth 角色成员关系、无 schema `CREATE` 或 28 表 `TRUNCATE`/`REFERENCES`；认证角色目前只获 schema `USAGE`。清理按唯一名称先关连接、删除 schema、再删除角色。
- 隔离验收入口先在 `0010_auth_version` 用迁移 owner 准备虚构种子，随后升级最终 head，以受限业务 engine 服务 HTTP；两引擎使用同一 schema。`scripts/check.sh` 对显式角色 URL 加本机 5433/测试库安全门。CI 配置普通业务登录，不让默认 HTTP engine 回退到 CI 超级用户；Hosted CI 尚未实际运行。
- 本项没有添加 RLS 策略或身份事务上下文。当前 28 表仍无生产 RLS 保护；临时业务角色的全表 DML 只供 T06 施工阶段旧主链运行，不构成生产权限设计。
