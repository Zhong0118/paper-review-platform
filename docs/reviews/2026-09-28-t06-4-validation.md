## 交付

`0012_rls_metadata` 对 `tenants`、`organizations`、`review_batches`、`discipline_catalog`、`experts`、`expert_conflicts`、`idempotency_keys`、`audit_events` 逐表启用并强制 RLS，累计 13/28 表。认证角色只可读取租户 `id/code/status`，因此仍能识别 `SUSPENDED` 并拒绝登录；不能读组织、论文或其他租户列。普通业务角色不能 SELECT 审计表，只能写与当前 actor/tenant 一致的事件；认证角色仅能写无 actor/tenant 的文件 `DENIED` 事件。审计服务改用无 `RETURNING` 的 inline INSERT，以匹配无 SELECT 权限。

组织 `(parent_id,tenant_id)` 的复合外键阻止跨校父组织。学校成员创建和学生建稿原有的 `SELECT FOR UPDATE` 分别需要锁租户、批次行；窄 UPDATE 策略保留锁，同时触发器阻止学校改租户、学生改批次。仅测试管理员的 superuser/BYPASSRLS 身份能在夹具中直接更新，真实业务角色仍受策略及触发器约束。并发探针现先绑定已验签身份再核对锁，R03 的四条并发回归通过。

独立只读复核发现认证账号可通过面向 `PUBLIC` 的业务审计策略伪造 `SUCCESS` 事件，以及 `0012→0011` 降级意外给认证账号全列租户读取与审计写入。两项均先加直接 SQL 失败测试，再把业务审计策略限定为业务数据库角色，并在降级时只撤销本项认证授权。复核未发现其余七表的高优先级策略问题；降级后的中间 revision 不作为可运行版本。
