## 结果与范围

新增 `0014_rls_workflow`（下接 `0013_rls_core`），对 `result_summaries`、`objections`、`workflow_events`、`termination_records` 启用并强制 RLS，累计 **23/28** 表。迁移先审核旧行的论文/轮次/学生 membership 与租户归属；冲突时拒绝升级。复合外键限制跨校父 ID，结果/异议父身份在普通账号 UPDATE 时不可更换；降级移除本项策略/约束，保留数据。

普通账号无身份时读不到这四表。学校仅本校汇总/异议/流程，学生仅本人论文异议及事件，导师仅已发布论文汇总，平台只读跨校流程事件，系统管理员无论文流程读取。汇总 SELECT 不依赖 `result_publications`；学校在 `COMPLETED` 后不能修改汇总，专家提交封轮次后也不能再改分数。直接 SQL 的 A/B 父 ID 混搭被拒绝。

原设计矩阵的专家汇总/流程写权限和学生流程写权限为空，但真实 `submit_final()` 会生成汇总与 `results_ready` 事件，学生 `submit()/withdraw()` 会生成事件；直接按原矩阵施工将中断主链。最窄修正见[设计矩阵](../superpowers/specs/2026-09-23-t06-rls-design.md)：学生只给本人论文的提交/撤回事件写入；专家只给本人已提交任务的封轮次汇总及 `results_ready` 事件写入。SQLAlchemy 的 `INSERT ... RETURNING` 还需要专家本人能读自己的该事件和发布前汇总。学校发布、学生异议 HTTP 主链保持通过。
