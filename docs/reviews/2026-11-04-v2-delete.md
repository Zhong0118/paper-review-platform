# BUG-08 · 从未提交草稿的删除与证据保留

验收边界 C-DELETE：学生可放弃自己的从未提交草稿，并在原批次重新创建；覆盖仅上传、检查后、PDF 转换 READY / APPLIED / CANCELLED。删除后旧详情、文件预览、已签发下载链接、转换重放均不可获取材料。检查、转换溯源与审计不得为删除草稿而放宽权限或丢失。不同学生不能删除；提交过即使撤回也不能删除。保留策略只处理本次草稿，不改变 TERMINATED 含义。

验证使用本机 5433/paper_review_test、每次独立 schema / 存储、受限业务连接与真实 PDF worker；只记录状态、代码、计数，不记录 token、文件或个人信息。

## 删除决策（0033）

3f40424 红测：同一套受限 HTTP 用例，纯上传 1 通过；检查、READY、APPLIED、CANCELLED 4 失败（DELETE 500）。检查表引用版本；转换表引用版本及产物文件的复合键。业务角色对二表均没有 DELETE。沿用对普通草稿的原有物理删除、解绑规则；只有存在检查或转换溯源时才将草稿标为已放弃。保留该草稿的原始版本、绑定、字节、报告、转换状态与审计，不伪造流程终止。旧证据无新读取入口。活跃批次唯一索引排除放弃标记，仍约束其他全部未终止论文。

不级联清理证据、不改外键、不新增运行角色授权。对 theses 及独立的文件、转换读取路径增加限制性策略。普通带 WHERE id 的 UPDATE 会因新行被 SELECT 策略隐藏而被 PostgreSQL 拒绝；在独立 5433 测试 schema 实测，先按主键 SELECT FOR UPDATE 的游标再 WHERE CURRENT OF 可只更新刚锁定的行，无需 SECURITY DEFINER 或特殊角色。提交/撤回历史、所有权和行锁仍是删除前提。物理清理既存证据、确定保留年限均不在本次决策内。

## C-DELETE · 脱敏 HTTP 记录

真实业务/认证 PostgreSQL 登录，HTTP 通过 ASGITransport；文件转换使用本机 Docker 镜像 `paper-review-pdf-worker:6.19.0`。所有样本为临时生成数据。以下结果来自 API 和数据库，未在浏览器重走。

| 操作 | 结果 |
|---|---|
| 学生创建草稿，上传并完成原文、匿名稿 | 200；可预览的学生原文、学校匿名稿各签发一个链接 |
| 可选敏感检查／生成 PDF 并保持 READY、应用或取消 | 200；转换产物在可预览时签发学生链接 |
| 学生 DELETE 自己的从未提交草稿；同批次 POST 新草稿 | 均 200，新论文 ID 不同；第二次 DELETE 旧 ID 返回 404 |
| 学生/学校旧详情、旧文件带登录凭据读取、删除前签发的下载链接 | 均 404；两方列表、批次办结清单不含旧 ID |
| 原转换操作再次 apply / cancel | 均 404；既存检查、转换源及产物引用、状态和审计行留存 |
| 异校学生按旧 ID 删除；学生本人提交后删除、撤回后再删除 | 异校学生 404；学生本人两次均 409，异校论文仍可读 |
| 转换进行中先放弃；提交与放弃争前后次序 | 真实转换完成后重新绑定被拒 404。两条真实受限会话实测已有等待锁：放弃先提交→后续 submit 404；提交先完成→delete 409 |
| 正在执行敏感检查时放弃 | 检测持锁，另一条业务连接从 PostgreSQL 确认等待；允许真实提取继续后检测返回 200，删除成功，管理端仍有 1 份报告；再发原检查请求返回 404 |

后置检查看旧业务角色视图和管理端留存分别验。初版把历史查询放进 UPDATE 策略，导致建稿时 `theses → workflow_events → theses` 策略递归；现改为只在写放弃标记时执行 SECURITY INVOKER 触发器。另补直接 SQL 红测：普通无 WHERE 的 UPDATE 曾能将已弃草稿的 READY 改为 CANCELLED（1 行），故转换与文件还必须有独立的限制性 UPDATE 策略。非学生文件权限仍沿用原有绑定可见性，未给专家增加对论文表的前置要求。

迁移无放弃标记时可往返；存在放弃标记时拒绝降到 0032，事务回滚，避免原草稿复活。对历史纯上传草稿仍采用既有文件解绑策略：保留的对象行可按原权限用于管理，其字节经旧链接及登录读取均 404。已弃的有证据草稿则保留完整关联；测试用独立管理连接核对文件字节摘要、检查、转换及审计。这里不声称删除了磁盘、备份或此前已下载的副本。
