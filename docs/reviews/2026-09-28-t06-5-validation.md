## 交付

`0013_rls_core` 对 `student_eligibilities`、`theses`、`thesis_versions`、`file_objects`、`review_rounds`、`expert_tasks` 启用并强制 RLS，累计 19/28 表。学生只能读本人论文与资格，学校只能读本校，平台可按既有职责跨校，导师仅能读本人指导关系下已发布论文；专家可读本人任务和任务论文，但不能直接 SELECT 论文版本。专家邀请标题从确认送出时冻结的 `review_rounds.anonymous_title` 读取，不再加载含摘要和关键词的版本整行。匿名文件仍须当前任务 `IN_REVIEW`、轮次 `ACTIVE`、论文 `UNDER_REVIEW`、版本为当前版本；原文文件不可读。

迁移先审计旧论文、版本、轮次、任务、文件的租户和父键关系；冲突会中断，不自动猜测或修补。任务论文 ID 和轮次标题由确定的父行回填；文件论文 ID 从上传版本或旧 link 推导，来源冲突拒绝，无法归属的旧孤儿保留 NULL。复合 UNIQUE/FK 校验当前版本、轮次版本、任务论文与替代任务、文件上传版本同属一篇论文和租户。新建轮次、派单、上传分别写入冻结标题和论文 ID；删纯草稿先解除 link，再同时清空文件两个归属键。学生锁资格用于现有建稿流程，实际资格 UPDATE 由触发器拒绝；专家为提交结果锁论文，论文父键不可直接改写。R02/R03 论文→任务及论文→文件锁顺序未改。

核心负向测试使用实际业务角色新连接：A 学生/学校看不到 B 论文；已知 B 版本不能改写 A 论文当前版本或轮次版本；任务不能改到 B 论文，文件不能改到 B 论文，学生不能为 B 成员插入 A 论文，系统管理员不能直接读论文。专家直接查版本与原文均为 0，但本人匿名文件与邀请标题可见。`CREATED` 轮次由本人学生改为 `CANCELLED` 后仍可读。旧数据测试先造上传版本与 link 指向不同论文，迁移明确拒绝；修正后可从两种来源回填、保留真正孤儿 NULL，降级后行数未丢。

独立只读复核指出两处重要问题并经红灯修复：旧 link-only 文件在删稿时遗留 `thesis_id`，触发 FK 拒绝删除；同一用户若有 A/B 两校历史 membership，A 校 token 可沿“本人”策略读 B 校行。前者改为按论文清理两归属键，旧 link-only 行只准双 NULL 脱钩且不能同时修改其他文件字段；后者在身份 membership 和资格/论文/轮次学生及导师策略中加入 token 租户限定。复核后无其他 Critical/Important 发现。
