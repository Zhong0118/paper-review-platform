## 1. 哪些操作真会绑定材料

| 入口（相对于 /api/v1） | 从哪个版本发起 | 返回值及含义 |
| --- | --- | --- |
| POST /files/{id}:complete | 必填请求头 `If-Draft-Revision`，值为当前编辑副本最后确认的 64 位小写十六进制 `current_version.content_revision` | 成功 200 含 `file_id, sha256, content_revision`。下一份材料应使用**刚确认**的版本；旧请求不会恢复已替换的材料。 |
| POST /pdf-transforms/{id}:apply | 同一必填头；同时保留 body `{"expected_version":1}` 的流程版本和转换来源/原绑定校验 | 成功 200 含 `operation_id, new_file_id, page_count, source_version, status:"APPLIED", content_revision`。重复应用仅在仍是该成品且能对上该快照时确认；不能拿旧预览覆盖其他修改。 |
| 准备上传、PUT 内容、complete-transform-source、生成预览、cancel | 不切换活动绑定，不要求此头 | 仍按所属人、材料版本、状态及原有授权规则办理。取消预览无权撤回已应用的成品。 |

缺头或格式错误均为 422；已观察到的有效指纹不匹配为 409 / VERSION_CONFLICT，不是“保存成功”。无权限或已弃资源按隐藏合同处理；比较隐藏资源行为时带合法输入，避免将框架参数校验当作授权。论文指纹标识内容和材料组合，与工作流 version、材料版本 ID、专家草稿整数 revision 均非同一对象。

**红测**：普通完成请求无条件地绑定成功（实际 200，预期 422）；另一页签替换匿名稿后旧的原稿转换仍应用成功（实际 200，预期 409）；前端组件原只传操作 ID 和流程版本。修复集中在 files router/service、transform router/service、论文内容指纹计算及前端 files/pdfTransforms 适配与对话框；锁顺序不变。

## 2. 丢回执之后，另一个页签已经保存

- 原有并增强的 `test_restricted_review_draft_compare_retry_and_submit`：两个独立 HTTP 客户端、受限事务。首次保存成功但当作未收到回执，原样重送返回同一 revision 1；其间已有第二次写入时，重送返回 409，data 为 `{"expected_revision":0,"current_revision":2}`，独立 GET 的**全部**内容等于第二次成功写入。再次把内容改回第一份，revision 已是 3；老请求仍返回 409，不能因文字碰巧相同而冒认回执。正式提交使用最新版本及原幂等语义。
- 原有组件测试 `replays an unacknowledged write before sending newer edits and serializes final with its ACK`（没有他页抢写）与新增 `keeps newer local edits when a lost acknowledgement is retried after another tab saved`（他页已写入）：后者注入网络错误与 409。前端先原样重送未知结果的命令，冲突后停在当前任务，不报已保存，不抢发后来的本地输入；允许查看服务器副本并保留本地文字。后端并发是实测，组件的断网是故障注入。此边界不需改普通评阅业务实现。
- 论文/材料以**内容指纹**比较，不宣称它是递增写入计数。普通上传完成响应丢失：不要自动换成最新头重发；先读论文详情核对具体 file_id、用途和用户输入，再决定。与上述专家整数版本合同分开。

## 3. 放弃后，哪些入口还能看见草稿

| --- | --- |
| 本人/学校列表、详情、批次收口、直接文件、已签链接、转换操作；历史和租户边界 | 原有 `test_abandon_draft_with_materials[uploaded/checked/READY/APPLIED/CANCELLED]`、`test_checked_draft_scope_and_submitted_history`：列表无旧 ID，详情与旧链接 404；新建 ID 不同；不可跨校删除，已提交不可删。受限角色不能读/复活原记录，受控管理验证保留的文件字节、检测、转换与审计。 |
| 直接命令及衍生投影 | 新增 `test_abandoned_draft_entrypoints_match_absent_resource_and_do_not_block_archive`：同一真实草稿先完成材料、检测并生成 READY 预览，同时留有未完成上传，再删除。PATCH、提交/撤回、学生与学校检测、确认/送出/终止/发布、学校进度详情/评分/导出 PDF、学生/导师发布结果、学生异议、平台候选/派单、再准备/写入/完成上传、重放生成及应用/取消均不返回旧资源。用合法输入断言 404；按 ID 的 JSON 命令核对 RESOURCE_NOT_FOUND。 |
