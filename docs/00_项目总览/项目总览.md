# 百杰校审平台项目总览

## 1. 项目定位

百杰校审平台是由百杰作为第三方运营方，为多所高校或科研机构提供学位论文送审与双向盲审管理的统一平台。平台拥有并维护共享专家库；租户学校负责学生身份、培养关系、送审批次、提交资格和异议处理等学校业务决定。

平台不是学校内部论文管理系统的替代品，也不是单纯文件上传工具。它连接学校权威数据、学生论文提交、百杰专家运营、专家在线评阅、结果发布和学校异议处置，并保证学校之间及盲审双方之间的信息隔离。

## 2. 建设目标

| 编号 | 目标 | 成功表现 |
|---|---|---|
| BR-001 | 支持百杰统一服务多个租户学校 | 学校数据隔离，平台专家可跨校服务但业务记录不互通 |
| BR-002 | 建立可验证的双向盲审机制 | 专家无法识别学生和导师；学生、导师和学校侧人员无法识别专家 |
| BR-003 | 跑通从资格同步到结果发布的送审闭环 | 每个阶段可追踪、可催办、可撤回、可改派并留痕 |
| BR-004 | 保持专家原始结果的真实性和可追溯性 | 汇总不覆盖原始结果，提交后锁定，更正保留版本 |
| BR-005 | 降低学校和百杰运营成本 | 支持在线提交、派单、评阅、提醒、导出和基础费用处理 |
| BR-006 | 为后续自动化保留清晰演进路径 | 自动匹配、自动匿名化、在线复核和自动代付可独立增强 |
| BR-007 | 支持百杰运营侧管理进度与费用 | 百杰侧可查看学生与专家身份以支撑派单、进度、结果和结算，且不破坏双盲与跨校隔离 |

## 3. 核心角色

平台固定五类核心角色：

| 编号 | 角色 | 核心职责 |
|---|---|---|
| ROLE-001 | 系统管理员 | 管理租户、账号、权限和系统配置；默认不接触论文或评阅内容 |
| ROLE-002 | 审核人员 | 学校侧负责送出、进度、结果和异议；百杰侧负责专家、派单和进度费用运营 |
| ROLE-003 | 学生/作者 | 基于学校资格提交本人论文、按专业方向选择拟送审范围、查看结果并提出异议 |
| ROLE-004 | 导师 | 结果发布后查看本人学生的分数和评语作为参考，不参与送审前审批；与学生共用学校身份渠道登录 |
| ROLE-005 | 专家 | 维护擅长评审领域，接受并完成分配给本人的匿名论文评阅任务 |

学校侧和百杰侧审核人员仍是同一核心角色，通过权限点和数据范围区分，不新增角色。平台运营侧（百杰侧审核人员及必要的平台管理职能）为支撑派单、进度和费用管理，可查看学生与专家身份，该可见性不构成学校之间的数据共享，也不解除专家与作者/导师之间的双向盲审隔离。

## 4. 核心业务闭环

```text
学校同步身份、培养关系、批次和提交资格
→ 学生登录并提交论文原始版、匿名版和附件
→ 系统检测、学校侧审核人员确认匿名版
→ 学校确认送出
→ 百杰侧审核人员从平台专家库人工派单
→ 专家接受/拒绝并在线评阅
→ 超时催审、延期或改派
→ 系统按学校规则汇总，冲突时补充评阅
→ 学校侧审核人员确认发布
→ 学生和导师查看匿名结果
→ 学生可登记异议，学校处理并回填结论
→ 完成与归档
```

## 5. MVP 范围

### 5.1 P0：首期必须交付

- 多租户、学校隔离和共享平台专家库；
- 学校主数据、提交资格和学生身份登录集成；
- 五角色权限与学校侧/百杰侧职责隔离；
- 原始版/匿名版提交、隔离、检测和人工门禁；
- 专家维护、资格状态、人工派单、显式接单/拒绝；
- 在线评阅、暂存、最终提交、更正申请；
- 接单超时、评阅逾期、催审、延期、改派；
- 评阅模板、评分、汇总规则、冲突和补充评阅；
- 结果确认发布及学生/导师匿名查看；
- 异议登记、提醒、状态和线下结论回填；
- 费用生成、余额、线上提现申请、人工付款回填；
- 站内通知和至少一种外部通知渠道；
- 审计、基础查询、导出、备份和恢复验证。

### 5.2 P1：优先增强

- 自动专家推荐；
- 自动生成匿名版；
- 完整在线复核送审；
- 支付机构自动代付和对账；
- 多渠道通知、批量能力和可视化规则配置；
- 文件水印、更多学校集成、运营看板；
- 学校级保留策略、异地备份和正式灾备 SLA。

### 5.3 P2：长期演进

- AI 辅助评审与评语质量检查；
- 查重和格式检测深度对接；
- 专家语义匹配、画像和质量评分；
- 微信小程序和移动端增强；
- 高级统计、风险预测、多区域与服务化治理。

## 6. 明确不属于 MVP

- 系统自动派专家；
- 自动修改论文生成匿名版；
- 平台自动裁定异议；
- 自动代付；
- 微服务、Kubernetes 或空业务占位实现；
- 未经学校规则授权的固定评分阈值。

## 7. 产品原则

1. 用户体验优先，但不牺牲盲审隔离和数据可恢复性。
2. 学校作学校业务决定，百杰作专家运营决定，系统管理员不代替任何一方。
3. 原始数据和历史记录不可被汇总、改派或更正覆盖。
4. 规则以租户学校或送审批次的已生效版本为准。
5. P0 做完整闭环；P1/P2 只保留清晰扩展边界，不提前过度实现。

## 8. 文档与编码门禁

- 本文及相关正式文档当前均为 `DRAFT`；
- 用户确认前不得标记 `APPROVED`；
- P0 必须具备需求到测试验收的完整追踪；
- 文档一致性和编码准入检查通过后，仍需用户明确回复“批准进入编码阶段”；
- 当前阶段只允许文档工作。
