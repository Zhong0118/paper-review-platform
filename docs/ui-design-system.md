# UI 设计系统

> 历史草案。现行视觉未按本文强制落地；改样式前再读。现状见 [CURRENT.md](CURRENT.md)。

本文件规定平台前端的**视觉与组件设计系统**，是 `docs/engineering-specification.md` 第 4 节的视觉细则。前端采用 **Tailwind CSS v4 + Element Plus** 双轨方案：**Tailwind 负责布局/间距/排版/业务自定义组件样式，Element Plus 负责表单/表格/弹窗/日期/上传/消息等交互组件**。所有颜色、字号、间距通过设计令牌（Design Token）使用，禁止在业务组件中散落硬编码值。

> 状态：本文件为 `DRAFT`，供用户评审。评审通过后，编码阶段作为前端 UI 的强制约束。

## 1. 设计目标与基调

平台面向高校学术评审场景，整体风格应体现：**专业、稳重、清晰、学术、可信**。高信息密度但不过度拥挤，重要流程必须让用户一眼看清“当前处于哪一步、谁可以看见什么、下一步由谁处理”。

- 禁止：过度娱乐化、强烈渐变、复杂玻璃拟态、大面积动画；
- 允许：克制的状态色、轻量反馈动画（≤200ms）、无阴影的边框区分；
- 盲审平台信息隔离：页面不得在 URL、文件名、日志或导出中携带被隔离身份（见 02 产品设计交互规则）。

### 1.1 品牌识别与设计签名

- Logo 与“百杰校审”名称在登录页、顶部栏和正式导出入口保持一致，不随角色改变品牌主体；角色名称作为次级上下文展示。
- 视觉签名采用“**双盲信息轨道**”：在论文、任务、评阅和结果等关键页面，用成对细线、角色可见性标签和阶段节点表达学生侧与专家侧的信息隔离。它必须承载真实权限信息，不作为纯装饰。
- 关键页面标题区优先展示业务对象、当前阶段和主要动作，不使用与业务无关的大数字卡片或装饰性渐变。
- 页面文案使用用户能识别的业务语言，如“确认送出”“接受任务”“最终提交”“确认发布”，动作完成后的反馈保持同一名称。
- 一屏只突出一个主要动作；身份隔离、安全提示和不可逆后果使用结构化提示条，不依赖弹窗堆叠。

### 1.2 Tailwind 与 Element Plus 分工边界

| 能力 | 归属 | 说明 |
|---|---|---|
| 布局、间距、排版、栅格、flex/grid | Tailwind | 原子类完成，业务组件不写布局 CSS |
| 表单控件（输入/选择/日期/上传/校验） | Element Plus | 含原生表单校验 |
| 表格、弹窗、抽屉、分页、消息提示 | Element Plus | 交互组件统一 |
| 业务自定义组件（状态标签、论文卡片、评阅表单、进度条） | Tailwind + 设计令牌 | 用令牌类组合，不另写魔法值 |
| 主题变量与令牌 | Tailwind `@theme` + Element Plus CSS 变量 | 两端同步（见第 2 节） |

原则：**Element Plus 管"交互与控件"，Tailwind 管"布局与视觉"**。业务页面优先用 Element Plus 组件 + Tailwind 原子类组织，不重复造组件库已提供的轮子；业务特有视觉（状态色、卡片、盲审标识）用令牌类。

## 2. 设计令牌（Design Tokens）

令牌在 **Tailwind v4 `@theme`（`frontend/src/styles/theme.css`）中定义一次**，同时映射到 Element Plus CSS 变量（覆盖 `--el-color-primary` 等），两端引用同一来源。业务组件只允许使用 Tailwind 语义类（如 `bg-primary`、`text-primary`、`text-secondary`）或 Element Plus 语义变量，禁止硬编码十六进制色值。

```css
/* frontend/src/styles/theme.css（示意） */
@import "tailwindcss";

@theme {
  --color-primary: #1B4F8A;
  --color-primary-hover: #2A63A6;
  --color-primary-active: #123D6B;
  --color-primary-soft: #E8F0F9;
  --color-blind-rail: #5B6B7A;
  --color-paper: #FBFCFE;
  --color-success: #2E7D32;
  --color-warning: #E65100;
  --color-danger: #C62828;
  --color-info: #0288D1;
  /* …中性色、字体、间距、圆角、阴影、断点见下文… */
}

:root {
  /* 同步到 Element Plus */
  --el-color-primary: var(--color-primary);
  --el-color-primary-light-3: #2A63A6;
  --el-color-success: var(--color-success);
  --el-color-warning: var(--color-warning);
  --el-color-danger: var(--color-danger);
  --el-font-size-base: 14px;
}
```

### 2.1 色彩体系

**主色：学术蓝**——用于主要操作、导航选中、重点信息。

| 令牌 | 值 | 用途 |
|---|---|---|
| `--color-primary` | `#1B4F8A` | 主按钮、链接、激活态 |
| `--color-primary-hover` | `#2A63A6` | 主按钮悬浮 |
| `--color-primary-active` | `#123D6B` | 主按钮按下 |
| `--color-primary-soft` | `#E8F0F9` | 主色浅底（标签/选中背景） |
| `--color-primary-50` | `#F4F8FC` | 页面浅底辅助区 |
| `--color-blind-rail` | `#5B6B7A` | 双盲信息轨道、权限边界辅助线 |
| `--color-paper` | `#FBFCFE` | 论文阅读、评阅内容的纸张底色 |

**语义色**：

| 令牌 | 值 | 用途 |
|---|---|---|
| `--color-success` | `#2E7D32` | 通过、完成 |
| `--color-warning` | `#E65100` | 临期、待处理 |
| `--color-danger` | `#C62828` | 驳回、失败、高风险 |
| `--color-info` | `#0288D1` | 提示性信息 |

**中性色**：

| 令牌 | 值 | 用途 |
|---|---|---|
| `--color-text-primary` | `#212121` | 主文字 |
| `--color-text-secondary` | `#616161` | 次要文字 |
| `--color-text-disabled` | `#9E9E9E` | 禁用文字 |
| `--color-border` | `#E0E0E0` | 分隔线、描边 |
| `--color-fill` | `#F5F5F5` | 输入框底、页面底 |
| `--color-bg` | `#FFFFFF` | 页面/卡片背景 |

颜色全部通过令牌类（`bg-primary`、`text-secondary` 等）或 Element Plus 语义变量使用。业务组件不得出现十六进制色值。

### 2.2 字体层级

| 令牌 | 字号 | 行高 | 字重 | Tailwind 类 | 用途 |
|---|---|---|---|---|---|
| `--font-h1` | 24px | 32px | 600 | `text-h1` | 页面主标题 |
| `--font-h2` | 18px | 26px | 600 | `text-h2` | 模块标题 |
| `--font-h3` | 16px | 24px | 600 | `text-h3` | 卡片标题 |
| `--font-body` | 14px | 22px | 400 | `text-body` | 正文 |
| `--font-body-sm` | 13px | 20px | 400 | `text-sm` | 表格/辅助 |
| `--font-caption` | 12px | 18px | 400 | `text-caption` | 辅助文字 |
| `--font-number` | 14px | 22px | 500 | `tabular-nums` | 数字/分数（等宽数字） |

正文行高不得低于 1.5。层级靠字号+间距+颜色，不靠大量加粗。字号在 `@theme` 中注册为 `--text-h1` 等，Tailwind 生成 `text-h1` 语义类。

### 2.3 间距体系（4px 基数）

`4 / 8 / 12 / 16 / 24 / 32 / 40 / 48`

- 页面主区域间距默认 24px；
- 卡片内部间距 16px 或 24px；
- 表单字段间距 16px（纵向）、12px（横向）；
- 列表行间距 8px。

间距在 `@theme` 中映射为 Tailwind 默认 spacing 语义类（`p-4`、`gap-6`、`mt-6` 等），不使用任意值魔法数字。

### 2.4 圆角

| 令牌 | 值 | 用途 | Tailwind 类 |
|---|---|---|---|
| `--radius-sm` | 6px | 表单控件 | `rounded-sm` |
| `--radius-md` | 8px | 卡片、弹窗 | `rounded-md` |
| `--radius-lg` | 12px | 大容器（受限） | `rounded-lg` |

不过度使用大圆角。

### 2.5 阴影

| 令牌 | 值 | 用途 | Tailwind 类 |
|---|---|---|---|
| `--shadow-none` | none | 普通卡片 | `shadow-none` |
| `--shadow-sm` | `0 1px 2px rgba(0,0,0,0.06)` | 悬浮态 | `shadow-sm` |
| `--shadow-md` | `0 4px 12px rgba(0,0,0,0.12)` | 弹窗、浮层 | `shadow-md` |

普通卡片优先用边框区分；阴影仅用于弹窗、浮层、必要悬浮。

### 2.6 断点与适配

| 断点 | 宽度 | 布局 |
|---|---|---|
| `--bp-xs` | <576px | 移动端堆叠 |
| `--bp-md` | 576–992px | 平板/窄屏两列 |
| `--bp-lg` | >992px | 后台桌面布局 |

断点映射到 Tailwind 默认断点（`sm`/`md`/`lg`），响应式用 `md:`/`lg:` 前缀类实现，不自定义魔数断点。管理端支持主流桌面浏览器；专家/学生关键流程支持移动浏览器自适应（NFR-011）。

## 3. 页面布局

### 3.1 全局宽度原则

- 页面根容器使用全部可用视口宽度，不设置全局 `max-width`，不定义 `--content-max`；
- 主内容区必须使用 `width: 100%`、`min-width: 0`，由栅格列、侧栏和内容优先级分配空间；
- 页面水平留白使用响应式内边距：移动端 12—16px、平板 20px、桌面 24—32px；大屏可增加边距，但不得把主内容压缩为固定居中窄栏；
- 长文本的可读性通过分栏、段落层级、字段跨度和局部阅读面板控制，不通过限制整页宽度实现；
- 表格、PDF 阅读器、规则编辑器、审计详情等高信息密度区域应充分利用宽屏空间。

### 3.2 四套角色骨架

学校后台、百杰运营后台和系统管理使用侧栏骨架：

```text
顶部栏（全局导航/用户）
左侧导航（模块菜单）
面包屑
页面标题区（标题 + 主操作）
筛选区（列表页）
主内容区（表格/表单/详情）
```

- 学校后台：围绕送审准备、进度、结果、异议和批次规则组织导航；
- 百杰运营后台：围绕专家、派单、更正、时效和结算组织导航；
- 系统管理：围绕租户、组织/批次同步、用户、角色和审计组织导航；
- 学生/导师与专家门户：顶部导航 + 任务聚焦内容区，不显示与当前角色无关的后台菜单；
- 移动端侧栏收为抽屉，顶部保留页面标题、返回和当前主要动作；
- 骨架用 Tailwind `flex/grid` 组织，页面级滚动与区域滚动不得互相抢占。

### 3.3 五类内容布局

| 页面类型 | 布局规则 | 代表页面 |
|---|---|---|
| 登录/入口 | 品牌区与登录区响应式分栏；窄屏上下堆叠，表单区随视口适配 | PAGE-001 |
| 数据列表 | 筛选、批量操作、表格纵向排列；表格占满主内容区，固定关键列 | PAGE-004—008、016、018—020、022 |
| 对象详情 | 主信息与状态/操作侧栏使用响应式栅格；窄屏按业务顺序单列 | PAGE-005、009、011—014 |
| 编辑表单 | 相关字段组成 1—3 列栅格；长文本、上传和规则编辑器跨整行 | PAGE-003、017、021、023 |
| 在线评阅 | 全视口双栏；左侧论文阅读、右侧评阅表，支持拖动分隔和分区滚动 | PAGE-010 |

### 3.4 在线评阅工作台

- 桌面端默认左右双栏，PDF 阅读区优先获得更大空间，评阅表单保持完整可操作；
- 分隔条可拖动，刷新后可恢复本人上次比例；不得用全局页面宽度限制阅读区；
- 两栏独立滚动，顶部任务信息和底部保存/最终提交操作保持可见；
- 窄屏切换为“论文 / 评阅表”双 Tab，保存草稿状态在两个 Tab 之间保持；
- 退出、刷新、网络失败和会话临期时优先保护已填写草稿。

### 3.5 大屏与移动端

- 大屏不简单放大字号，应增加可见列、对比面板或详情分栏，减少无意义空白；
- 表格在窄屏转换为保留主标识、状态和主要动作的卡片列表，次要字段进入详情；
- 移动端不得通过水平缩放整张后台页面解决适配；确需横向滚动的表格应固定首列和操作列；
- 学生上传、专家接单/评阅、结果查看和异议提交必须在移动浏览器完成核心动作。

## 4. 通用组件规范

### 4.1 表格（数据密集结构化展示）

- 首列一般为主要标识；操作列固定右侧；
- 操作 >3 个收进"更多"下拉；危险操作红色文字 + 二次确认；
- 空值统一显示 `--`；日期时间统一格式 `YYYY-MM-DD HH:mm`；状态用统一状态标签组件；
- 必须支持加载、空数据、错误三态；大数据列表后端分页（服务端 cursor）；
- 表格列宽可拖拽不强制；长文本省略并 tooltip。
- 默认使用中等密度；数据量较大的运营列表允许用户切换紧凑密度，但行高不得低于可访问点击区域要求；
- 宽屏优先增加有决策价值的列，不用空白占位；列过多时按“标识—状态—时间—责任—操作”优先级折叠；
- 表头、筛选条件和导出字段使用同一业务术语，避免一处叫“阶段”、另一处叫“状态”。

### 4.2 表单

- 简单表单单列；复杂表单可两列但相关字段相邻；
- 标签位置统一（左对齐，`--form-label-width` 90px）；必填/选填清晰；
- 帮助文字放字段下方；保存/取消按钮位置一致（右下）；
- 字段级错误 + 可恢复操作；校验失败聚焦首个错误字段。
- 表单不设置统一固定宽度；输入控件按字段语义占据栅格列，摘要、评语、规则和文件区跨整行；
- 学校权威只读字段与平台可编辑字段必须分组并标注来源，避免用户误以为可在平台修正主数据。

### 4.3 按钮层级

- 每操作区通常只有一个主按钮；
- 层级：`Primary`（主要）/ `Default`（次要）/ `Text`（弱）/ `Danger`（危险）；
- 禁止同一区域多个同权重主按钮；危险操作红色 + 二次确认。

### 4.4 弹窗与浮层

- 弹窗圆角 8px；遮罩默认半透明；居中展示；
- 二次确认弹窗说明影响范围（如"确认发布后学生将可见结果"）；
- 弹窗和抽屉按内容复杂度占用视口比例，不使用全项目统一固定像素宽度；简单确认保持紧凑，复杂表单优先使用抽屉或独立页面；
- 关闭按钮、Esc、点击遮罩关闭策略统一（危险表单弹窗默认禁止遮罩关闭）。

### 4.5 状态标签

状态使用统一 `StatusTag` 组件，映射见 02 唯一枚举表：

| 状态示例 | 色 |
|---|---|
| DRAFT/SUBMITTED | 中性灰 |
| PREPARING/READY_FOR_DISPATCH | 信息蓝 |
| UNDER_REVIEW/IN_REVIEW | 主色蓝 |
| COMPLETED/SUCCESS/PAID | 成功绿 |
| `overdue=true`/逾期/临期 | 警告橙（附加属性，不作为任务主状态） |
| TERMINATED/REJECTED/FAILED | 危险红 |

### 4.6 图标

统一使用项目指定图标库（Element Plus Icons 或约定图标库）；图标必须语义明确；禁止混用多个风格不一致的图标库。

## 5. 导航、标题与反馈

### 5.1 导航层级

- 顶部栏承载品牌、当前租户/角色上下文、通知和用户菜单；侧栏只放当前角色可访问的一级模块；
- 多角色用户切换上下文后，菜单、首页和数据范围同时刷新，并明确显示当前角色与学校；
- 面包屑表达真实层级，不把筛选条件或弹窗步骤塞入面包屑；
- 菜单隐藏不能替代服务端权限校验，无权限路由由服务端投影和前端路由守卫共同处理。

### 5.2 页面标题区

- 标题区包括页面名称、必要的对象标识、状态标签和一个主要动作；
- 列表页面的统计只展示能驱动处理的数量，如“待确认”“即将超时”“待发布”，不放装饰性指标；
- 详情页优先显示阶段、责任方和下一步；双盲对象使用匿名编号，不在不应出现的角色端拼接真实身份。

### 5.3 反馈与状态

- 加载反馈：按钮 loading、表格 loading、骨架屏，不使用整页转圈占位大面积阻塞；
- 空状态：图标 + 说明 + 引导动作；
- 错误状态：可重试按钮；
- 动效克制 ≤200ms，仅 hover/active/过渡反馈；
- 滚动容器统一内边距与滚动条样式。

操作反馈必须复述用户刚执行的动作和结果，例如“已保存草稿”“已确认送出”“结果已发布”；失败提示说明原因、数据是否保留和下一步恢复动作，不使用只有“操作失败”的笼统文案。

## 6. 甲方演示与真实内容规范

- 演示优先覆盖“学生提交 → 学校确认 → 百杰派单 → 专家评阅 → 学校发布 → 学生查看”的完整闭环；
- 演示数据使用统一学校、批次、论文和状态时间线，跨页面的姓名、编号、数量和日期必须一致；
- 演示环境仍遵守双盲投影，不因是假数据就在学校端展示专家姓名或在专家端展示学生身份；
- 关键页面同时准备正常、空数据、失败、逾期、冲突和无权限状态，现场只展示与讲解目标相关的状态；
- 不使用“测试数据 1”“张三论文”“Lorem ipsum”等占位文案；论文题目、专业方向、评语和通知应符合高校论文评审语境；
- 视觉演示稿与字段级原型共享 PAGE 编号，评审意见能够追溯到正式页面文档。

## 7. 可访问性基线

- 键盘可操作、可见焦点；语义标签；错误提示关联；
- 正文对比度 ≥ 4.5:1；大字号 ≥ 3:1；
- 颜色不单独传达信息（同时用文字/图标辅助）；
- 焦点顺序与视觉顺序一致。

## 8. 与工程规范的关系

## 9. 第二批甲方演示补充

### 9.1 四端菜单

- 学生：我的论文、评审结果与异议、消息通知；
- 学校：送审准备、评审进度、结果处理、异议处理、批次与评审规则、学校账户与账单、消息通知；
- 百杰运营：送审运营台、专家库、评阅更正审批、费用结算、消息通知、审计查询；
- 专家：我的任务、费用与提现、个人资料与资格、消息通知。

论文编辑和在线评阅等带具体业务对象的页面从列表动作进入，不作为脱离上下文的一级菜单。

### 9.2 数据列表与详情

列表页使用“处理数量摘要 → 状态分组 → 筛选 → 表格 → 详情抽屉”的统一层次。学校送审准备、百杰送审运营台、专家任务和学校账单都必须同时具有加载、空数据、错误重试和无权限状态。

### 9.3 专业选择与帮助文案

专业选择器默认收起，点击或聚焦后展开，支持代码与名称搜索、门类分组、点击外部和 `Esc` 关闭。学科专业与关键词的帮助文案放在字段下方，不使用只有图标的不可发现提示。

### 9.4 演示控制

角色快速切换、主线阶段与场景重置只在演示模式中显示，在正式模式中不渲染且不占位。演示设定使用单专家、300 元任务费用和六项 100 分评阅表，这些值仅来自演示批次规则快照。
