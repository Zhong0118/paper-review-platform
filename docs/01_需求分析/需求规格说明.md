# 百杰校审平台需求规格说明

## 1. 需求规则

- `BR-*` 表示业务目标；`FR-*` 表示功能需求；`NFR-*` 表示非功能需求；
- P0 必须实现并通过验收，P1/P2 仅记录演进边界；
- 所有“可配置”规则必须有版本、生效范围和审计记录；
- 本文不定义学校尚未提供的固定专家人数、分数阈值或保留年限。

## 2. P0 功能需求

### 2.1 租户、身份和权限

| 编号 | 需求 | 验收摘要 |
|---|---|---|
| FR-001 | 系统管理员可创建、启停和配置租户学校 | 租户停用后禁止新业务，历史数据不丢失 |
| FR-002 | 学校系统可同步学生、导师、组织、批次和提交资格 | 同步可幂等重试；按学校配置 JSON 字段映射，映射可版本化调整；学校权威字段在平台只读 |
| FR-003 | 用户按五类核心角色和数据范围访问功能 | 菜单隐藏不能替代服务端权限校验 |
| FR-004 | 学校间业务数据严格隔离 | 任一跨租户 ID、列表、导出或文件访问均拒绝并审计 |
| FR-005 | 学校侧与百杰侧审核人员执行职责隔离 | 学校侧不见专家身份；百杰侧为支撑派单、进度、结果与费用管理可查看学生/导师身份，但不得外泄给学校侧或专家侧 |

### 2.2 论文提交与匿名化

| 编号 | 需求 | 验收摘要 |
|---|---|---|
| FR-006 | 有效资格论文通过学生自主提交、学校单篇代传或学校批量导入创建统一论文记录 | 无资格或过期批次不可创建/提交；学校提交无需学生二次确认；记录来源、操作人和时间 |
| FR-007 | 提交方必须分别上传原始版和匿名版及必需附件 | 文件类型、大小、可读性和必填项校验明确；学生自提被退回后只能由学生本人修改 |
| FR-008 | 原始版与匿名版隔离保存并执行不同访问策略 | 专家永远不能访问原始版 |
| FR-009 | 系统检测匿名版中的身份线索 | 至少覆盖姓名、学号、导师、致谢、文件名和文档元数据 |
| FR-010 | 学校侧审核人员确认匿名版和材料完整性 | 未通过时阻断送审并退回草稿/重新提交 |
| FR-011 | 学生在派单前可撤回至草稿 | 既有提交和撤回记录保留 |
| FR-012 | 派单后学生可申请撤回 | 由学校侧审核人员决定，批准后终止轮次并保留历史 |

### 2.3 专家库与派单

| 编号 | 需求 | 验收摘要 |
|---|---|---|
| FR-013 | 百杰维护平台共享专家库和资格状态 | 专家填写擅长评审领域用于派单匹配；专家可服务多校，学校不见其他学校使用记录 |
| FR-014 | 百杰侧审核人员人工选择专家并创建任务 | 可按送审专业方向、专家擅长领域与学科检索候选，执行回避检查；只可读取匿名论文和必要学科信息 |
| FR-015 | 改派必须关闭原任务并创建新任务 | 不覆盖原专家、邀请、草稿或状态历史 |
| FR-016 | 论文版本改变或正式复核时创建新送审轮次 | 普通拒绝、超时和改派仍在原轮次内 |

### 2.4 专家接单与评阅

| 编号 | 需求 | 验收摘要 |
|---|---|---|
| FR-017 | 专家必须显式接受或拒绝任务 | 接受前只见匿名基本信息；拒绝必须记录原因 |
| FR-018 | 接单超时自动关闭任务并通知改派 | 不自动选择替代专家 |
| FR-019 | 专家接单后可查看完整匿名版并填写评阅 | 只能访问本人有效任务，不能见其他专家 |
| FR-020 | 专家可暂存草稿并最终提交 | 暂存可修改；最终提交校验模板并锁定；评阅支持分项打分（系统计算平均分）或直接总分加评语，由学校/批次规则版本化决定 |
| FR-021 | 评阅逾期只标记和催审 | 不自动删除草稿；审核人员选择延期或改派 |
| FR-022 | 已提交结果的更正需要申请和批准 | 新版本生效，原版本永久保留 |

### 2.5 结果、发布与异议

| 编号 | 需求 | 验收摘要 |
|---|---|---|
| FR-023 | 分别保存每位专家原始结果 | 汇总、更正或发布不得覆盖原结果 |
| FR-024 | 按学校/批次已生效规则计算汇总 | 支持分项平均或总分两种模式，均保留各专家原始结果；无规则时只展示独立结果，不推断结论 |
| FR-025 | 达到冲突条件时标记并允许补充评阅 | 补充任务属于当前轮次，重新汇总有效结果 |
| FR-026 | 学校侧审核人员确认后发布结果 | 发布前学生、导师不可见；专家身份始终隐藏 |
| FR-027 | 学生和导师查看各专家分数、获准评语和汇总 | 返还结果展示分数与评语；导师只能看本人学生，学生只能看本人 |
| FR-028 | 学生可登记异议并上传材料 | 学校负责处理；平台跟踪状态、提醒和结论回填 |

### 2.6 费用、通知、审计和导出

| 编号 | 需求 | 验收摘要 |
|---|---|---|
| FR-029 | 有效评阅生成专家费用和可提现余额 | 重复事件不得重复计费，撤销规则可追踪 |
| FR-030 | 专家可提交提现申请 | 百杰人工审核、线下付款并回填，不自动代付 |
| FR-031 | 平台提供站内通知和至少一种外部渠道 | 发送结果、失败原因、重试和去重可追踪 |
| FR-032 | 关键业务和文件访问必须审计 | 包含操作人、时间、租户、对象、前后状态和追踪号 |
| FR-033 | 授权用户可导出进度、结果、评阅书和结算 | 导出异步生成、权限校验、7 天失效并记录下载 |
| FR-034 | 平台提供基础业务进度查询 | 不跨租户、不破盲，统计口径与状态模型一致 |
| FR-035 | 学校使用学校账户额度承担送审费并查看账单 | 学生不付款；送审按批次费用快照冻结，有效评阅后扣减；额度不足阻止创建任务；学校额度与专家余额独立 |

## 4. 非功能需求

| 编号 | 分类 | 要求 |
|---|---|---|
| NFR-001 | 安全 | 所有业务权限在服务端执行，默认拒绝，跨租户越权返回统一拒绝且不泄露资源存在性 |
| NFR-002 | 隐私 | 日志、通知和导出不得出现不必要身份、Token、银行卡或完整联系方式 |
| NFR-003 | 可用性 | 关键状态变化、最终提交、派单、发布和计费必须幂等，可安全重试 |
| NFR-004 | 并发 | 派单、撤回、最终提交、发布使用版本检查或等价并发控制，冲突不得静默覆盖 |
| NFR-005 | 性能 | 草案目标：普通业务接口 P95 1 秒内、复杂列表/统计 P95 3 秒内，文件传输除外；编码前需基于用户量、文件量和峰值任务量确认负载条件后冻结 |
| NFR-006 | 文件 | 单文件上限由租户配置；MVP 必须校验 MIME、扩展名、大小、可读性和加密状态 |
| NFR-007 | 审计 | 关键审计记录只追加，不允许业务用户修改或删除 |
| NFR-008 | 可恢复 | 数据库和对象文件每日备份，保留最近 7 个恢复点，上线前完成联合恢复验证 |
| NFR-009 | 可维护 | 模块通过小接口承担完整行为，禁止跨模块直接修改状态或数据库表 |
| NFR-010 | 可测试 | 时间、通知、存储、学校集成等可变外部能力通过适配器接入，可使用测试适配器 |
| NFR-011 | 兼容性 | 管理端支持当前主流桌面浏览器，专家/学生关键流程支持移动浏览器自适应 |
| NFR-012 | 可观测 | 请求、任务和通知使用 trace_id/correlation_id 关联日志、审计和异步任务 |

## 5. P1/P2 需求边界

P1 包括自动专家推荐、自动匿名版生成、完整在线复核、自动代付、多渠道通知、批量增强、水印、更多学校适配、运营看板和高级灾备。P2 包括 AI、查重深度对接、语义匹配、专家画像、小程序、高级分析和服务化。P1/P2 在各自进入实施前必须补充分解需求、数据、API、测试和验收，不以空代码预留。

## 6. 业务规则版本化

以下规则必须按租户/批次版本化并记录生效时间：

- 学校主数据同步的字段映射（JSON 配置，按学校调整字段匹配）；
- 提交字段和附件要求；
- 匿名化检测清单；
- 评阅模板、评分项、分值范围和必填规则（分项打分或总分+评语）；
- 目标专家人数、接单和评阅期限；
- 汇总与冲突条件；
- 异议期限和状态；
- 费用规则和提现门槛；
- 通知模板。

任务创建时必须快照适用规则版本，后续修改不得改变历史任务和结果。
