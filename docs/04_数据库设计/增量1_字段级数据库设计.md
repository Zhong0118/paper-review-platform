# 增量 1 字段级数据库设计（C0 + C1）

本文件是 `docs/04_数据库设计/数据库设计.md` 的增量细化，覆盖实施计划 C0（基础工程）与 C1（用户、组织与权限）涉及的字段级结构，作为首个实施增量的 Alembic 迁移依据。仅作设计，不代表已经获得编码授权。

## 1. 通用字段规范

所有表遵循 `docs/04_数据库设计/数据库设计.md` 第 2 节：`id` 为 UUID 服务端生成；`created_at`/`updated_at` 为 `timestamptz`（存 UTC）；`created_by`/`updated_by` 为 UUID 可空；需要乐观锁的聚合根带 `version int`；业务历史不物理删除。枚举一律引用 `docs/02_产品设计/产品与流程设计.md` 第 7 节唯一枚举表。

迁移顺序建议：先建 `tenants`（其他表的外键依赖），再建 `organizations`/`review_batches`，随后 `users`/`tenant_user_memberships`/`roles`/`user_role_assignments`，再建 `student_eligibilities`/`external_sync_records`，最后启用 RLS 与索引。破坏性变更拆分版本，采用扩展—迁移—收缩。

## 2. C0 基础表（无业务表）

C0 不新增业务表。Alembic 初始化空迁移基线；`async_jobs`（TABLE-039）虽属公共能力，但通知/导出任务在后续增量使用，本增量仅建表不建任务实现，`async_jobs` 具体字段在 C11/C14 细化时冻结。C0 交付健康检查（不依赖业务表）。

## 3. C1 字段级设计

### 3.1 `tenants`（TABLE-001）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | uuid | PK | |
| `code` | varchar(32) | NOT NULL UNIQUE | 学校编码，用于对象存储前缀等 |
| `name` | varchar(128) | NOT NULL | 学校名称 |
| `status` | enum | NOT NULL DEFAULT `ACTIVE` | `ACTIVE`/`SUSPENDED`/`CLOSED` |
| `sync_mapping` | jsonb | NOT NULL DEFAULT '{}' | 同步字段映射 JSON；版本化见 4.1 |
| `config_version` | int | NOT NULL DEFAULT 1 | 配置乐观锁版本 |
| `suspended_at` | timestamptz | NULL | 停用时间 |
| `created_at`/`updated_at` | timestamptz | NOT NULL | |
| `created_by`/`updated_by` | uuid | NULL | |

约束：`code` 唯一；停用后禁止新业务由应用层校验 + 批次状态约束共同保证。

### 3.2 `organizations`（TABLE-002）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | uuid | PK | |
| `tenant_id` | uuid | NOT NULL FK→tenants | 必填 |
| `external_id` | varchar(64) | NOT NULL | 学校系统组织标识 |
| `parent_id` | uuid | NULL FK→organizations | 组织树父节点 |
| `org_type` | enum | NOT NULL | `COLLEGE`/`MAJOR`/`DEPT`/`OTHER` |
| `name` | varchar(128) | NOT NULL | 组织名称 |
| `source_updated_at` | timestamptz | NULL | 源系统更新时间（幂等排序） |
| `is_active` | boolean | NOT NULL DEFAULT true | 停用语义，不物理删除 |
| `created_at`/`updated_at` | timestamptz | NOT NULL | |

约束：`(tenant_id, external_id)` 唯一；`(tenant_id, parent_id)` 上外键保证同租户内树。

### 3.3 `review_batches`（TABLE-003）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | uuid | PK | |
| `tenant_id` | uuid | NOT NULL FK→tenants | |
| `code` | varchar(32) | NOT NULL | 批次编码（如 2026-春） |
| `name` | varchar(128) | NOT NULL | 批次名称 |
| `status` | enum | NOT NULL DEFAULT `DRAFT` | `DRAFT`/`OPEN`/`SUBMISSION_CLOSED`/`ARCHIVED` |
| `start_at` | timestamptz | NULL | 开始时间 |
| `end_at` | timestamptz | NULL | 截止时间 |
| `rule_version` | int | NOT NULL DEFAULT 1 | 批次规则版本快照引用 |
| `created_at`/`updated_at` | timestamptz | NOT NULL | |

约束：`(tenant_id, code)` 唯一；批次规则版本引用在 C6 起冻结（`review_batches.rule_version` 关联规则快照表，本增量只预留列，规则快照表在 C6/C9 细化）。

### 3.4 `users`（TABLE-004）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | uuid | PK | 平台账户 |
| `username` | varchar(64) | NULL UNIQUE | 平台登录名（专家/审核人员/管理员） |
| `password_hash` | varchar(255) | NULL | 自适应哈希；学校 SSO 用户可为空 |
| `status` | enum | NOT NULL DEFAULT `ACTIVE` | `ACTIVE`/`DISABLED`/`LOCKED` |
| `display_name` | varchar(128) | NULL | 展示名 |
| `contact_phone` | varchar(32) | NULL | 最小化收集，脱敏展示 |
| `contact_email` | varchar(128) | NULL | |
| `last_login_at` | timestamptz | NULL | |
| `created_at`/`updated_at` | timestamptz | NOT NULL | |

约束：`username` 唯一（可空，SSO 用户可为空但需有 `tenant_user_memberships.external_id` 关联）；平台账号与租户关系在 `tenant_user_memberships` 维护，`users` 不直接保存学校资格。

### 3.5 `tenant_user_memberships`（TABLE-005）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | uuid | PK | |
| `tenant_id` | uuid | NOT NULL FK→tenants | |
| `user_id` | uuid | NOT NULL FK→users | |
| `organization_id` | uuid | NOT NULL FK→organizations | 所属组织（学院/专业） |
| `membership_type` | enum | NOT NULL | `STUDENT`/`SUPERVISOR`/`STAFF`/`OTHER` |

| `source_updated_at` | timestamptz | NULL | 幂等排序依据 |
| `created_at`/`updated_at` | timestamptz | NOT NULL | |

约束：`(tenant_id, external_id)` 唯一；`(tenant_id, user_id)` 唯一（同租户内一用户一条成员关系，一人可跨租户多行）；外键到组织保证同租户。

### 3.6 `roles`（TABLE-006）

## 4. 同步字段映射 JSON

### 4.1 `tenants.sync_mapping` 结构

学校系统字段名 → 平台统一模型字段名，按租户配置、可版本化。缺失或类型不符时同步记录 `FAILED`。

```json
{
  "version": 1,
  "source_system": "graduate_sys",
  "student": {
    "external_id": "xh",          // 学号
    "display_name": "xm",          // 姓名
    "organization": "xy",          // 学院
    "degree_type": "xwlx",         // 学位类型
    "supervisor": "ds"             // 导师标识
  },
  "organization": {
    "external_id": "xyid",
    "name": "xymc",
    "parent_external_id": "sjxyid"
  },
  "batch": {
    "external_id": "pcid",
    "name": "pcmc",
    "start_at": "kssj",
    "end_at": "jssj"
  },
  "eligibility": {
    "batch_external_id": "pcid",
    "status": "zkzt"
  }
}
```

### 4.2 映射变更

映射变更递增 `tenants.config_version`，旧版本由审计与配置版本记录保留；任务创建/同步执行时快照所用映射版本。

## 5. RLS 策略（C1 租户隔离）

- `organizations`/`review_batches`/`tenant_user_memberships`/`student_eligibilities`/`external_sync_records` 启用 RLS，策略为 `tenant_id = current_setting('app.current_tenant')::uuid`；
- `tenants` 为平台级表，不启用租户 RLS，但应用层限定；
- `users`/`roles` 为平台账户表，不启用租户 RLS；`user_role_assignments` 学校角色行按 `tenant_id` 启用 RLS；
- 连接上下文：`SET app.current_tenant = ...; SET app.current_user = ...`，由 `db/session.py` 统一设置；
- RLS 为第二道防线，应用查询仍显式带租户条件。

## 6. 索引基线

- 所有租户业务表以 `(tenant_id, ...)` 为首列索引；
- `organizations(tenant_id, external_id)` 唯一索引；`review_batches(tenant_id, code)` 唯一索引；
- `tenant_user_memberships(tenant_id, external_id)`、`(tenant_id, user_id)` 唯一索引；
- `student_eligibilities(tenant_id, student_membership_id, review_batch_id)` 唯一索引；
- `external_sync_records(tenant_id, sync_job_id, external_id, record_type)` 唯一索引；
- `user_role_assignments(user_id, tenant_id, role_id, effective_from)` 唯一索引。

## 7. 回滚与迁移

- 每个表迁移独立版本，破坏性变更拆分；
- 回滚按表逐级向下（先 `external_sync_records`，最后 `tenants`）；
- RLS 策略迁移单独一个版本，回滚时先移除策略再移除表；
- 种子数据（平台租户、五角色）用幂等 upsert，重放不产生重复。
