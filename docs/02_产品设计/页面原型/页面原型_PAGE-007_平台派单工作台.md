## 三、字段与组件

| 区 | 字段/组件 | 类型 | 约束 |
|---|---|---|---|
| 待派单列表 | 匿名论文号/送审方向/学校/待派人数 | Table | 匿名论文 + 必要学科信息 |
| 候选专家 | 复选框 + 专家姓名/擅长领域/回避命中/历史 | Table | 回避命中行禁止勾选并提示原因 |
| 操作 | 指派/改派/催审/延期 | Button | 指派改派二次确认 + 幂等键 |
| 运营分组 | 待派单/待接单/评阅中/即将逾期/已逾期/待改派/待补审/已完成 | Tabs+Statistic | 分组为运营队列，不增加论文宏观状态 |

## 四、交互与状态

- 候选按送审专业方向、专家擅长领域、回避规则过滤（T-016）；
- 命中回避：勾选禁用，提示原因；不允许强制跳过（AC-011）；
- 并发指派：两审核人员同时操作返回 `VERSION_CONFLICT`，不产生重复任务（TC-012）；
- 改派：关闭原任务（`CANCELLED`）并在同轮新建，保留历史；
- 催审/延期：记录操作与期限变更；
- 学生/导师身份可显示（运营需要，Q-014），原始版不可见。
- 候选同时展示单位/职称、专业与擅长领域、当前负载、接单率和按时完成率；P0 只做可解释排序和人工最终选择。
- 演示批次的目标专家数为 1、任务费用为 300 元；其他批次仍按已生效规则版本配置。

## 五、数据来源与权限投影

- 数据来源：`GET /platform-review/dispatch-candidates`、`POST /review-rounds`、`POST /review-rounds/{id}/tasks`、`POST /expert-tasks/{id}:reassign`、`POST /expert-tasks/{id}:remind|extend`；
- 百杰运营侧可见学生/导师与专家身份（派单/进度/费用管理，Q-014）；
- 原始版不可见；学校侧不可见此页；
- 学校间使用记录不可见（平台专家跨校复用不互通）。

## 六、前端演示实现（2026-08-12）

以下为百杰运营端前端演示证据，仅表示页面可交互闭环，不代表真实 API、数据库或通知发送已接入。

- 实现页面 `DispatchWorkbenchPage.vue`（送审运营台，PAGE-007）：十条运营队列（待匹配/专家待接受/评阅中/即将逾期/已逾期/已拒绝待改派/邀请超时/更正处理中/待结算/已完成）由平台任务状态投影派生，队列计数随指派、接单、提交等操作实时更新。
- 待派列表选择论文后展示候选专家：排序依据（接单率/按时完成率/平均完成时间/费用标准）可解释，命中回避规则的候选自动禁选并提示原因；单专家评审约束，一次只能指派 1 位；指派前二次确认，确认后生成 `INVITED` 评审任务并进入「专家待接受」队列。
- 忙队列（待接受/评阅中/即将逾期/已逾期）支持催审与延期（二次确认、写运营审计）；已拒绝队列支持改派（选择替代专家并填写原因，原任务关闭保留历史）。
- 费用规则快照 `FeeRuleSnapshot` 只读展示本批次固化金额（¥ 300.00），页面不可手工改写；候选专家宽表在 ≤900px 视口自动切换为卡片视图，390px 无整页横向滚动。
- 页面右下角在 `VITE_DEMO_MODE=true` 时提供运营端演示场景控制器（PENDING_DISPATCH/CORRECTION_PENDING 等场景装载、一键恢复默认数据），关闭演示模式时不渲染入口。
- 演示实现为内存场景服务（localStorage 键 `baijie-demo-platform:v1`）的不可变投影；真实派单 API、队列服务端分页与通知发送未实现。
