# PAGE-011 结果处理工作台

## 一、页面信息

| 项 | 值 |
|---|---|
| 页面 | 结果处理工作台 |
| 角色 | 学校侧审核人员 |
| 入口 | 学校端菜单"结果处理" / 送审进度"结果" |
| 关联 API | API-024 去标识结果、API-025 发布；补审由百杰侧 API-016 执行 |

## 三、字段与组件

| 区 | 字段/组件 | 类型 | 约束 |
|---|---|---|---|
| 汇总区 | 汇总规则/汇总分/冲突标记 | 只读 | 规则快照；冲突仅标记不裁定 |
| 结果表 | 匿名结果标识/分数/获准评语 | Table | 专家身份隐藏；原始结果只读 |
| 冲突处理 | 补审处理状态/查看进度 | StatusTag+Link | 学校侧只读；百杰侧在 PAGE-007 创建同轮次补充任务 |
| 操作 | 确认发布 | Button | 服务端返回允许动作；发布二次确认 + 幂等键 |

## 四、交互与状态

- 无汇总规则：仅展示各独立结果，不显示汇总/不推断结论；
- 冲突命中：标记 `CONFLICT` 并展示百杰补审处理状态；学校侧不得直接创建专家任务或编辑专家分数；
- 补审结果纳入后由系统重新汇总并生成新汇总版本（不覆盖旧版本），学校侧不直接触发计算命令；
- 确认发布：进入 `COMPLETED`，学生/导师可见，专家身份始终隐藏；
- 发布后如有补审变化：创建新发布记录，不修改历史发布。

## 五、数据来源与权限投影

- 数据来源：`GET /school-review/results`、`POST /result-summaries/{id}:publish`；补充任务由百杰侧 `POST /review-rounds/{id}:supplement` 执行；
- 仅本租户；可识别学生；不出现专家身份；
- 学校侧审核人员不得修改专家原始分数（AC-017）。
