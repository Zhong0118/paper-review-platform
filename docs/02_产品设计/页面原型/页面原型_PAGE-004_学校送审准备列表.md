# PAGE-004 学校送审准备列表

## 一、页面信息

| 项 | 值 |
|---|---|
| 页面 | 学校送审准备列表 |
| 角色 | 学校侧审核人员 |
| 入口 | 学校端菜单"送审准备" |
| 关联 API | API-010 确认匿名化、API-006 查看草稿 |

## 三、字段与组件

| 区 | 字段/组件 | 类型 | 约束 |
|---|---|---|---|
| 筛选区 | 批次/状态/学生搜索 | Select+Input | 过滤本租户 |
| 列表 | 学生/论文题目/提交时间 | Table | 学生可识别（学校侧）；专家身份不出现 |
| | 检测结论 | StatusTag | `PASS/FAIL/REVIEW_REQUIRED` |
| | 材料完整性 | StatusTag | 附件/原件/匿名件齐备 |
| 操作 | 确认匿名化 | Button | 二次确认；`READY_FOR_DISPATCH` 前进 |
| | 退回 | Button(danger) | 需填退回原因；回 `DRAFT` |
| | 查看 | Button | 打开匿名件/检测项详情 |
| 批量 | 批量确认 | Button | 二次确认 + 逐项成功/失败 |

## 四、交互与状态

- 列表三态：加载/空/错误；
- 确认匿名化通过：论文进入 `READY_FOR_DISPATCH`；
- 退回：填写原因，论文回 `DRAFT`，学生收到通知；
- 检测 `FAIL` 的论文由系统阻断并退回 `DRAFT`，不进入本确认队列；
- 检测 `REVIEW_REQUIRED` 时展示结构化命中项，由学校人工确认通过或退回；`PASS` 仍需完成材料与匿名版最终确认；
- 批量操作逐项记录成功/失败，不无解释部分提交（API 设计 2.3）。

## 五、数据来源与权限投影

- 数据来源：`GET /school-review/theses`、`POST /school-review/theses/{id}:confirm-anonymization`、`POST /school-review/theses:batch-confirm-anonymization`；
- 仅本租户；可识别学生，不出现专家身份/联系方式；
- 原件与匿名件分域，学校侧可访问两者（管理用途）。
