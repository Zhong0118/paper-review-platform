# PAGE-020 评阅更正审批

## 一、页面信息

| 项 | 值 |
|---|---|
| 页面 | 评阅更正审批 |
| 角色 | 百杰侧审核人员 |
| 入口 | 百杰运营端菜单“更正审批” / 通知中心更正申请 |
| 关联 API | API-023 更正申请与审批 |

## 三、字段与组件

| 区 | 字段/组件 | 类型 | 约束 |
|---|---|---|---|
| 列表 | 申请号/专家/匿名论文号/时间/状态 | Table | 百杰运营范围；服务端分页 |
| 详情 | 原版本/原因/拟更正差异/证据 | Diff+Description | 原版本永久只读 |
| 审核 | 审核意见 | Textarea | 批准或驳回均必填 |
| 操作 | 驳回/批准 | Button | 二次确认、幂等、乐观锁 |

## 四、交互与状态

- 百杰审核人员只能批准或驳回更正申请，不得直接编辑专家原始分数或评语；
- 批准后由服务端按申请内容生成新的评阅版本，旧版本永久保留并建立版本关系；
- 若原结果已发布，页面必须提示影响范围；后续汇总和重新发布按版本化结果流程处理，不静默覆盖历史发布；
- 并发审批返回 `VERSION_CONFLICT`，页面刷新申请状态，不重复生成版本；
- 驳回必须记录原因并通知申请专家。

## 五、数据来源与权限投影

- 数据来源：`GET /correction-requests`、`GET /correction-requests/{id}`、`POST /correction-requests/{id}:decide`；
- 百杰侧可见申请专家身份和必要运营信息，但不得访问论文原始版；
- 学校侧、学生和导师不访问本页；获准发布的结果变化通过结果发布流程投影。

## 六、前端演示实现（2026-08-12）

以下为百杰运营端前端演示证据，仅表示页面可交互闭环，不代表真实 API、数据库或通知发送已接入。

- 实现页面 `CorrectionApprovalPage.vue`（评阅更正审批，PAGE-020）：更正申请列表（待处理/已批准/已驳回筛选）、详情面板 `CorrectionDetailPanel` 展示申请专家、更正原因与当前版本内容；审批必须填写审核意见，批准/驳回写运营审计。
- 版本管理：专家申请更正后原版本保留（`CURRENT` 只读）；平台批准后生成新版本 R2（`CURRENT`），原版本 R1 标记 `SUPERSEDED` 只读保留并建立版本关系；驳回不改动版本。
- 与专家端闭环联动：专家在评阅工作台提交更正申请 → 本页待处理队列计数 +1；批准后更正处理中队列清空，专家端通知关联跳转。
- 页面右下角在 `VITE_DEMO_MODE=true` 时提供运营端演示场景控制器（CORRECTION_PENDING 等场景装载、一键恢复默认数据），关闭演示模式时不渲染入口。
- 演示实现为内存场景服务（localStorage 键 `baijie-demo-platform:v1`）的不可变投影；真实更正审批 API、版本持久化服务与通知发送未实现。
