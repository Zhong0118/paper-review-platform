## 4. 覆盖结论

当前 35 项 P0 功能需求均已形成主要追踪链路，但设计覆盖不等于后端实现完成。2026-08-10 已同步 Q-002 增量决定：统一论文记录支持学生自提、学校单篇代传和学校批量导入，学校提交无需学生二次确认，专业保存代码+名称，关键词保存数组。学校付费和额度账单已追踪至 FR-035、PAGE-024、API-038、TABLE-041—043 与 TC-025。

第二批前端甲方演示已经形成 PAGE-001—024 的真实页面路由，并以可重置的内存场景服务贯通学生提交、学校审核与额度冻结、平台单专家派单、专家六维评阅、学校发布结果及专家费用入账。自动化证据为 22 个测试文件、44 项单元测试、类型检查及生产构建；浏览器检查覆盖 1920×1080、1440×900 和 390px 关键视口。该证据只表示前端演示实现：API-036—038、TABLE-041—043、真实 SSO、文件解析、通知发送、导出生成和支付结算仍未实现。正式文档继续保持 `DRAFT`，未经用户确认不提升为 `APPROVED`。

学生交互闭环（2026-08-11）在第二批演示之上补齐学生端可保存、可提交、可撤回、可查看结果与提交异议的完整路径：学生黄金路径自动化测试覆盖“保存完整草稿 → 提交学校审核 → 装载已完成快照 → 提交异议 → 跨服务实例重建后阶段与异议状态不丢失”，全量单元测试 32 个文件、166 项全部通过，类型检查与演示模式生产构建通过；浏览器人工检查覆盖 1440×900、1920×1080 和 390×844 三视口的学生登录、论文切换与详情、材料编辑、专业悬浮搜索、关键词上限、文件失败/重试、保存、提交、撤回、结果、异议、消息跳转、场景切换与重置。该证据仅标记学生前端演示：真实学生 API、数据库、SSO、文件解析、匿名检测和通知发送均未实现；学校、运营、专家、导师的静态页面仍按各自演示计划记录，本计划未将其标记为交互闭环完成。

运营与专家端交互闭环（2026-08-12）在第二批演示之上补齐运营端与专家端完整路径：平台黄金路径自动化测试覆盖“资格审核 → 派单 → 接单 → 六维评阅 → 最终提交 → 申请更正 → 平台批准（版本 R1/R2）→ 提现 → 付款回填（凭证幂等）→ 跨服务实例重建全链路持久化”，并回归“装载结算快照后继续派单→接单→提交不被陈旧结果锁吞掉”与“场景装载清除陈旧评阅草稿”两个跨场景一致性问题；专家端工作台测试覆盖草稿恢复、缺项/越界校验、提交锁定、只读、更正申请对话框复位等页面交互。全量单元测试 342 项通过（另有 6 项为用户本地未接入场景服务的基线用例，不在本计划通过范围），类型检查与演示模式生产构建通过；浏览器人工检查覆盖 1440×900、1920×1080 和 390×844 三视口的运营登录、专家库（筛选/详情/暂停接单）、运营台（队列切换/派单/改派/催审）、更正审批、结算处理，以及专家登录、任务列表（Tab/接受/拒绝）、在线评阅（六维/草稿/提交/只读/申请更正）、资料与提现、消息跳转、场景切换与重置；390px 下队列与候选专家表格卡片化、无整页横向滚动、对话框焦点与 Esc 行为正确。该证据仅标记运营与专家前端演示：真实平台/专家 API、数据库、SSO、文件解析、通知发送与支付结算均未实现；学校、导师与学生的静态页面仍按各自演示计划记录，本计划未将其标记为交互闭环完成。
