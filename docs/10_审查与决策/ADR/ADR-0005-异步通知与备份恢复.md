# ADR-0005 异步通知与备份恢复

## 状态

P0 最低能力已由用户确认；外部通知具体渠道待实施环境确定。

## 背景与问题

提醒、超时、导出和外部通知不应阻塞业务事务；同时论文数据库与对象文件必须能够一致恢复，不能为了快速上线完全省略灾难恢复底线。

## 候选方案

- A：请求内同步执行所有副作用，无正式备份演练。
- B：Redis/Celery 异步任务，站内加一个外部渠道；每日数据库和对象备份、7 个恢复点、上线前联合演练。
- C：首期即建设多地域消息平台和自动灾备。

## 选定方案

选择 B。业务事实先在数据库事务中提交，异步副作用以幂等任务执行。Beat 负责扫描和调度，不作为事实来源。备份覆盖 PostgreSQL 与对象存储，临时导出 7 天过期。

## 理由与影响

方案满足快速交付和最低可靠性。代价是需要管理任务重试、失败队列和联合恢复一致性。正式 RPO/RTO、异地备份、季度演练和自动灾备进入 P1。

## 后续约束

通知必须去重、可重试、可追踪且最小化敏感内容。上线前没有联合恢复证据不得通过发布准入。
