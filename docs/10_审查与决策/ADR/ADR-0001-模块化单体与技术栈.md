# ADR-0001 模块化单体与技术栈

## 状态

业务和技术方向已由用户确认；ADR 文本等待正式评审。

## 背景与问题

平台需要快速交付完整盲审闭环，同时保持租户、安全、工作流、文件和财务边界，避免首发阶段承担微服务运维复杂度。

## 候选方案

- A：模块化单体，按领域分模块，进程内应用服务协作。
- B：从首期开始拆分微服务。
- C：无明确模块边界的传统分层单体。

## 选定方案

选择 A。前端采用 Vue 3、TypeScript、Vite、Element Plus；后端采用 FastAPI、SQLAlchemy 2、Alembic；使用 PostgreSQL、Redis/Celery、MinIO/S3、Nginx、Docker Compose。Java 仅在真实外部集成需要时作为独立适配器引入。

## 理由与影响

模块化单体能以较低部署成本保持清晰领域边界和事务一致性。负面影响是边界依赖工程纪律，不能依赖网络强制隔离。模块必须拥有自己的领域规则、应用服务和数据访问，不允许跨模块直接更新私有表。

## 后续约束

只有出现独立扩缩、合规隔离或团队自治的实证需求时才评估拆服务。微服务、Kubernetes 和多地域不属于 P0。
