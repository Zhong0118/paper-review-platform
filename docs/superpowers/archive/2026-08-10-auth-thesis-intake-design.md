# 登录、账号激活与双通道论文接入设计

## 1. 目标与范围

本设计解决甲方演示前暴露的三个连续问题：用户如何进入系统、论文如何由学生或学校接入、接入后的论文如何进入统一送审流程。首轮只实现前端演示服务和交互，不接真实 SSO、Excel 解析、短信、邮件或支付机构。

本设计覆盖：

- PAGE-001 登录与受邀账号激活；
- PAGE-002 学生多论文管理表格；
- PAGE-003 论文编辑、专业代码和关键词 Tag；
- PAGE-004 学校单篇代传、批量导入预览和论文管理；
- PAGE-005 学校确认送出与任务进度；
- PAGE-007/PAGE-009 中专业匹配和评审费用的展示边界。

## 2. 已确认决策

1. 学生、导师通过学校身份渠道登录；专家、学校管理员、百杰运营和系统管理员使用平台账号。
2. 平台不开放普通公开注册。专家和学校管理员采用“平台邀请 -> 受邀人激活 -> 设置平台密码”的方式建立账号；百杰运营和系统管理员由平台内部创建。
3. 登录页提供“平台账号”“学校身份”“激活受邀账号”三类明确入口；演示模式额外保留五个角色快捷入口。
4. 学校身份入口使用学校代码或学校专属链接定位租户，不在未认证页面公开列举全部学校。
5. 论文采用统一记录、双通道接入：学生可自行提交；学校可单篇代传或批量导入。
6. 学校代传可直接提交进入材料审核，不要求学生再次确认；系统必须记录接入来源、操作人和时间。
7. 学生登录后能看到学校为本人代传的论文，但不能把学校权威字段改成其他学生或其他专业。
8. 专业必须从“专业代码 + 专业名称”目录中选择，不允许自由输入；关键词使用 Tag 输入并去重。
9. 专家人数、评审期限、评阅模板和评审费用来自批次规则快照，不照搬旧系统“每篇固定两个专家”的规则。
10. 首轮派单页只读展示规则快照中的费用，不提供费用编辑入口。

第 5—7 项是对 Q-002 原决定的增量调整：保留学校权威主数据和学生自助提交，同时恢复旧材料中的学校单篇/批量代传能力。正式文档同步时必须保留原决定并记录本次变更。

## 3. 方案比较

### 方案 A：统一论文记录 + 双通道接入（选定）

学生提交和学校代传调用同一领域服务，生成相同的论文、文件、匿名检测和审计结构，仅通过 `submissionSource` 区分来源。

- 优点：不产生两套状态机；学生和学校看到同一事实；最适合逐步替换旧系统。
- 代价：必须处理重复学号/批次/论文、字段主责和代传审计。

### 方案 B：学校批量导入使用独立暂存区

批量数据先形成独立“导入记录”，人工确认后才创建正式论文。

- 优点：复杂 Excel 校验和错误修正更清晰。
- 代价：页面和状态更多；甲方演示链路变长。

方案 A 仍会保留“导入预览”作为提交前的临时前端状态，但不会把它建模成第二套长期业务流程。

### 方案 C：学校代传为唯一入口

- 优点：最接近旧平台。
- 缺点：失去学生在线提交价值，与已经完成的学生端冲突。

因此选择方案 A。

## 4. PAGE-001 登录与激活设计

### 4.1 页面结构

右侧登录卡使用三个入口标签，避免一个表单同时承担不同身份渠道：

```text
┌ 平台账号 | 学校身份 | 激活受邀账号 ┐
│                                      │
│ 平台账号：账号、密码、登录、忘记密码 │
│ 学校身份：学校代码、继续学校认证      │
│ 账号激活：邀请编码、校验邀请          │
│                                      │
│ 演示模式：五个角色快捷入口            │
└──────────────────────────────────────┘
```

“学校身份”说明学生和导师适用；“平台账号”说明专家及管理人员适用。学校代码只用于定位 SSO 配置，界面不返回学校内部数据。演示模式选择角色后直接进入角色默认页。

### 4.2 激活状态

- 未校验：填写邀请编码；
- 有效邀请：只读显示受邀角色与机构，允许设置密码；
- 过期/已使用：给出明确原因和“联系邀请方重新发送”；
- 激活完成：返回平台账号登录，不自动假设已经登录。

真实邀请校验、密码设置和找回密码需要正式认证 API；前端演示只呈现状态，不伪造真实账号写入。

## 5. 论文数据与字段主责

### 5.1 统一论文摘要

```ts
interface ThesisSummary {
  id: string
  studentId: string
  studentName: string
  title: string
  batchName: string
  disciplineCode: string
  disciplineName: string
  keywords: string[]
  submissionSource: 'STUDENT' | 'SCHOOL_MANUAL' | 'SCHOOL_BATCH'
  stage: ThesisStage
  updatedAt: string
  allowedActions: string[]
}
```

`studentId`、学生姓名、学校、学院、专业/学科目录、导师、批次和资格属于学校权威字段。论文题目、摘要、研究方向、关键词和文件属于论文内容字段。学校代传时可以填写论文内容字段，但不能脱离已同步学生记录凭空创建身份。

### 5.2 专业目录

- 选择器同时搜索专业代码和名称；结果显示“代码 · 名称”；
- 选择结果同时保存代码和名称，不允许只传文本名称；
- 目录来源为租户/批次已生效配置；演示数据使用虚构目录；
- 已提交论文显示当时的目录快照，后续目录改名不能悄悄改写历史；
- 没有匹配代码时阻止提交并提示联系学校管理员更新目录。

### 5.3 关键词 Tag

- 回车或分号生成 Tag；自动去除首尾空格并阻止完全重复；
- 支持键盘删除和按钮删除；
- 不在首轮擅自设置关键词数量或长度上限，后续由批次/学校规则确定；
- 关键词用于检索辅助，不替代专业代码的匹配主维度。

## 6. PAGE-002 学生多论文管理

学生工作台从单卡片改为表格，支持同一学生跨批次或多论文记录：

| 列 | 内容 |
|---|---|
| 论文 | 题目、匿名论文号 |
| 批次 | 批次名称 |
| 专业方向 | 代码 + 名称 |
| 接入来源 | 学生提交/学校代传/批量导入 |
| 状态 | 论文主状态 + 逾期等附加标记 |
| 更新时间 | 绝对时间 |
| 操作 | 由 `allowedActions` 决定编辑、查看或查看结果 |

顶部保留资格信息和流程解释，但不再假设学生永远只有一篇论文。移动端表格改为逐条卡片，不横向压缩关键字段。

## 7. PAGE-004 学校论文接入与管理

### 7.1 页面结构

- 顶部动作：“单篇代传”“批量导入”“下载导入模板”；
- 筛选：批次、学院、专业代码、接入来源、匿名检测、论文状态、学生学号/姓名；
- 表格：学生学号、学生姓名、题目、专业代码/名称、来源、文件状态、匿名检测、论文状态、更新时间、操作；
- 学校侧始终不显示专家姓名、联系方式或专家库。

### 7.2 单篇代传

采用侧边抽屉或独立页面，顺序为：选择已同步学生 -> 选择批次/专业目录 -> 填论文内容和关键词 -> 上传原始版/匿名版 -> 校验 -> 直接提交。提交确认文案必须明确“将以学校代传身份提交，学生无需再次确认”。

### 7.3 批量导入

演示流程：选择 PDF 集合和论文信息表 -> 解析预览 -> 行级错误提示 -> 只提交校验通过项。预览至少覆盖：

- 学号能否匹配本校已同步学生；
- 批次和提交资格是否有效；
- 专业代码是否存在；
- 同一学生、批次和论文是否疑似重复；
- 原始版和匿名版文件是否齐全；
- 文件名、格式和匿名线索检查结果。

首轮前端用固定演示数据展示预览和错误分流，不声称已经真实解析 Excel 或 PDF。

## 8. PAGE-005/PAGE-007 送出、匹配与费用

学校在 PAGE-005 只确认材料与匿名版并送出，不选择具体专家，也不看到专家身份。PAGE-007 由百杰运营按专业代码、专家擅长领域、关键词辅助信息和回避结果筛选候选专家。

评审费用显示批次规则快照值，创建专家任务时随任务保存。PAGE-009 专家接受邀请前可以看到本任务费用和结算说明。费用入账仍以有效最终评阅为触发条件；首轮不实现自动打款。

如果未来允许运营人员覆盖单个任务费用，必须另行确认覆盖权限、原因、审批和审计规则，本规格不提前实现。

## 9. 前端模块边界

- `modules/auth`：登录入口、邀请激活、账号渠道文案；
- `modules/thesis`：学生论文表格、论文编辑、专业选择、关键词 Tag；
- `modules/school`：学校论文表格、单篇代传、批量导入预览、确认送出；
- `modules/dispatch`：候选专家、专业匹配说明、规则费用展示；
- `demo`：多论文 fixtures、学校导入预览和统一场景服务；页面不得直接修改 fixtures。

页面只消费统一服务返回的数据和 `allowedActions`，不自行推断角色可执行动作。

## 10. 异常与隐私

- 重复论文、无资格、未知专业代码和缺文件必须在提交前分行显示；
- 首轮前端只实现批量导入预览和行级校验，不执行真实批量写入；“整批原子提交”或“有效行部分成功”须在后端批量接口设计前另行决策；
- 学校代传写入来源、操作人和时间；学生侧显示“由学校代传”，不显示后台人员敏感信息；
- 学校页面不出现专家身份；专家页面不出现学号、学生姓名、导师或原始版文件；
- 金额使用最小货币单位或 Decimal 表达，前端不使用浮点累计。

## 11. 测试与验收

1. 正式模式不显示演示角色入口；演示模式显示全部五个角色。
2. 学校身份入口没有学校代码时不能继续；平台账号和邀请激活互不串用字段。
3. 学生表格能同时展示学生提交和学校代传论文。
4. 专业选择结果同时包含代码和名称；自由文本不能绕过目录校验。
5. 关键词生成 Tag、去重和删除行为可测试。
6. 学校单篇代传无需学生确认即可进入材料审核，并保留来源。
7. 批量导入预览逐行区分有效、重复、未知专业和缺文件。
8. 学校页面序列化内容不含专家身份；专家页面不含学生身份。
9. 费用由批次规则快照展示，不出现任意编辑入口。
10. 桌面和移动视口均完成登录、学生表格、学校表格与导入预览的视觉检查。

## 12. 实施顺序

1. 优化 PAGE-001 登录三入口和演示角色入口；
2. 抽取专业代码选择器与关键词 Tag 组件；
3. 将 PAGE-002 改为学生多论文表格；
4. 更新 PAGE-003 专业与关键词字段；
5. 实现 PAGE-004 学校论文表格、单篇代传和批量预览；
6. 实现 PAGE-005 学校确认送出与进度；
7. 实现 PAGE-007 专业匹配和规则费用展示；
8. 同步问题与决策记录、正式页面原型、API/数据设计和测试追踪。
