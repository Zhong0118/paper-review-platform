# 甲方演示第二批四端管理页与单专家主线设计

## 1. 目标与范围

第一批前端已经建立登录、学生/学校论文接入、学校审核、百杰派单、专家评阅和结果发布的骨架。本设计以甲方现场演示为目标，将单卡片或单详情页补齐为可管理的列表和工作台，并使同一篇论文在学生、学校、百杰运营和专家端保持状态一致。

本批覆盖：

- 四端菜单与管理型页面边界；
- 单篇主线论文与多条固定辅助数据；
- 学生多论文、专业目录搜索、关键词 Tag 和双文件提交；
- 学校学生申请审核、单篇代传、批量导入、进度、结果和账务；
- 百杰送审运营台、完整专家库、更正审批和结算；
- 专家任务列表、接单、六项动态评阅表、费用和资格；
- 通用 UI、异常恢复、演示控制和验收。

本批不实现真实 SSO、真实 Excel/PDF 批量解析、自动匿名版生成、自动专家匹配或支付机构对接。

## 2. 选定方案

采用“一篇论文完整演示主线 + 每个角色真实管理表格”的混合方案。页面使用同一演示场景服务，不直接修改 fixtures；主线操作改变共享状态，固定辅助数据用于展示退回、逾期、改派、补审和历史结果，不因主线推进而消失。

通用业务模型仍支持学校/批次配置多名专家；甲方演示批次明确配置为单专家，不将“单专家”写成平台永久限制。

## 3. 演示场景与状态

### 3.1 主线论文

| 字段 | 演示值 |
|---|---|
| 学校 | 海岳大学 |
| 批次 | 2026 年春季硕士论文盲审 |
| 学生 | 林知远（学校、学生与导师投影可见） |
| 盲审编号 | `HY-2026-0042`（系统生成、不可编辑） |
| 论文 | 面向复杂场景的多模态知识推理研究 |
| 送审专业 | `0812 计算机科学与技术` |
| 提交来源 | 学生自主提交 |
| 目标专家数 | 1 |
| 任务费用 | 300 元 |

主线顺序为：学生提交 → 学校材料/匿名审核 → 学校确认送审并冻结额度 → 百杰人工指派 → 专家接单/评阅 → 学校发布 → 学生查看。

### 3.2 状态分层

论文宏观状态仅使用正式状态机：`DRAFT` → `SUBMITTED` → `PREPARING` → `READY_FOR_DISPATCH` → `UNDER_REVIEW` → `RESULT_PROCESSING` → `COMPLETED`。

“待派单”是百杰运营队列；“待接单/评阅中/已提交”是专家任务状态；逾期是任务的时限属性。前端演示不得再把这些子状态伪造成论文宏观状态，也不同时使用 `COMPLETED` 和 `PUBLISHED` 表示两个完成节点。

### 3.3 辅助数据

列表额外预置匿名不合格、学校代传待送审、评阅逾期、待补审和已完成各一条。这些数据只用于表格、筛选和异常态展示，不要求现场逐条推进。

## 4. 信息架构

### 4.1 学生端

主菜单为“我的论文”、“评审结果与异议”、“消息通知”。论文编辑不是一级菜单，由新建、继续填写或退回修改动作进入。

### 4.2 学校端

主菜单为“送审准备”、“评审进度”、“结果处理”、“异议处理”、“批次与评审规则”、“学校账户与账单”、“消息通知”。

### 4.3 百杰运营端

主菜单为“送审运营台”、“专家库”、“评阅更正审批”、“费用结算”、“消息通知”、“审计查询”。原“派单工作台”扩展为送审全程运营台。

### 4.4 专家端

主菜单为“我的任务”、“费用与提现”、“个人资料与资格”、“消息通知”。在线评阅从具体任务进入，不作为无上下文的一级菜单。

## 5. 学生与学校页面

### 5.1 学生论文列表

表格展示盲审编号、题目、批次、专业代码/名称、提交来源、当前阶段、更新时间和服务端允许动作。详情抽屉展示状态时间线。学校代传和批量导入记录对学生可见，不需学生二次确认。

### 5.2 论文编辑与匿名文件

学号、姓名、学校、学院、硕士/博士、学术/专业学位、导师和批次是学校权威只读字段。学生填写题目、摘要、送审专业和关键词；专业从带版本的研究生学科专业目录中按代码或名称搜索，关键词以 Tag 录入并去重。

学生分别上传原始版和匿名版。匿名版保留学术内容，移除或遮蔽姓名、学号、导师、致谢、页眉页脚、文件名和文档元数据等身份线索。P0 由学生/学校准备匿名版，系统检测，学校人工确认；不自动生成匿名版。

### 5.3 学校送审准备与进度

“送审准备”将学生申请、学校单篇代传和批量导入收口到统一列表，按待审核、已退回、待确认送审和全部分组。学生提交被退回后必须由学生本人修改；学校代传可由同一管理员修改、审核和确认送审，各动作分别写审计。

“评审进度”展示论文阶段、任务数量、截止时间与异常标记，不展示专家身份。结果处理只读展示专家原始评阅，学校不得修改分数或评语，确认后发布。

### 5.4 学校账户与账单

新增 PAGE-024，展示可用额度、冻结额度、累计/当月消费以及按盲审编号追溯的账单。学校确认送审时按批次费用快照冻结 300 元；专家提交有效结果后转为已消费。学校额度不足时禁止确认送审，但不删除已通过的材料审核结果。

## 6. 百杰运营与专家页面

### 6.1 送审运营台

PAGE-007 从单一派单详情扩展为待派单、待接单、评阅中、即将逾期、已逾期、待改派、待补审和已完成标签页。派单抽屉展示匿名论文、规则快照和候选专家；按专业、擅长领域、资格、负载、完成率与回避结果排序。P0 只做候选解释与人工最终选择，回避命中、资格无效或服务停用时禁止指派。

### 6.2 平台专家库

PAGE-006 表格展示姓名、单位、职称、学科/擅长领域、资格、服务状态、当前负载、接单率与按时完成率。详情抽屉管理基本资料、资格材料、回避、历史任务、费用摘要和操作日志。学校不能访问专家库。

### 6.3 专家任务与评阅

专家任务列表按待接单、评阅中、即将截止、已逾期和已提交分组。接单前只展示匿名题目/摘要、专业、期限、费用和评审要求；接受后才能读取完整匿名版。

在线评阅使用全视口可拖动双栏，左侧匿名 PDF，右侧按模板版本渲染的评阅表。演示模板为选题价值 15、文献与理论基础 15、研究方法 20、创新性 25、研究成果与工作量 15、写作与学术规范 10，合计 100；并包含综合结论、优点、问题、修改建议和总体评语。该模板是演示批次快照，不是平台硬编码唯一模板。

## 7. 费用与账务边界

送审费由学校承担，学生无支付入口。P0 使用学校账户额度：百杰录入线下充值或合同额度，学校确认送审时冻结，有效评阅形成后扣减并生成账单。专家的可提现余额由有效评阅收入形成，与学校额度是两个独立账务边界。

未配置费用规则、额度不足或账务写入失败时不得创建新送审任务。取消或改派按已生效规则释放或保留额度，不覆盖原流水。P0 不调用线上充值或自动代付。

## 8. 通用 UI 与异常

- 页面根容器使用完整可用宽度，不设全局 `max-width`；
- 表格支持筛选、加载、空数据、错误重试和无权限状态；
- 专业选择器默认收起，点击/聚焦后打开，点外部或 `Esc` 关闭；
- 危险动作二次确认，并说明影响范围；
- 学生/专家关键流程支持移动端，后台以桌面端为主；
- 上传失败、匿名检测失败、额度不足、并发指派和最终提交失败均保留已录入数据并给出可恢复动作；
- 最终评阅提交后只读锁定，更正走版本申请。

## 9. 演示控制与隔离

仅在 `VITE_DEMO_MODE=true` 时展示角色快速切换、主线当前阶段和重置场景入口。正式模式完全不渲染这些控件，也不得静默回落到演示数据。演示数据仍执行双盲投影，不因为是虚构数据而跨角色泄露身份。

## 10. 验收与测试

黄金流程必须在一次重置后连续完成：学生提交双文件 → 学校审核与确认送审 → 冻结 300 元 → 百杰人工指派 → 专家接单、保存草稿、按六项模板提交 → 学校发布 → 学生查看 → 学校账单转已消费、专家生成 300 元收入。

至少验证：正式状态分层、允许动作、身份投影、专业搜索与 Tag 去重、学校双入口、匿名退回、额度冻结/扣减、候选专家禁用原因、专家草稿/最终提交、结果发布和非演示模式禁止假数据回落。每批实施后运行相关 Vitest、全量单元测试、TypeScript 检查和生产构建，并在 1440×900、1920×1080 和约 390px 移动宽度下人工检查关键页面。

## 11. 实施边界

本设计先以前端演示服务完成可视化闭环，但演示服务接口需与正式 API 资源边界一致。学校额度、账单、批量导入、专家库和运营台的正式后端接口与迁移仅在对应实施批次进入时创建；前端不得声称本地场景数据已实现真实账务、文件或支付处理。
