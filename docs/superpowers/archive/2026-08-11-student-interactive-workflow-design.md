# 学生端交互闭环设计

## 1. 背景与结论

现有学生端已经具备论文列表、论文编辑、专业选择、关键词 Tag、双文件展示和结果页的视觉骨架，但部分控件仍是静态演示：专业菜单会占据文档流，论文详情和撤回不可操作，学生可见进度与所选论文未绑定，结果页缺少异议闭环，刷新后也没有明确的演示状态策略。

本轮按 Q-018 只完成学生角色。采用“真实业务操作 + 独立演示状态切换”方案：学生业务页面只提供学生依法可执行的动作；演示模式额外提供与业务区隔离的场景控制器，用于查看学生无法自行推进的下游阶段。所有学生页面共用一个可持久化的前端场景状态，后续学校、百杰运营和专家端继续接入该状态模型。

## 2. 范围

### 2.1 本轮包含

- PAGE-002 学生论文工作台；
- PAGE-003 论文编辑与上传；
- PAGE-012 学生结果与异议；
- PAGE-015 中与学生相关的消息交互；
- 学生可见的五阶段进度、详情时间线和责任提示；
- 论文草稿保存、提交、派单前撤回、派单后撤回申请、结果查看和异议提交；
- 专业目录搜索、关键词 Tag、双文件及附件的前端交互；
- 演示状态持久化、场景切换和一键重置；
- 桌面与移动端关键流程。

### 2.2 本轮不包含

- 真实文件上传、病毒扫描、PDF 解析或匿名线索检测；
- 真实学校 SSO、学生主数据同步和提交资格接口；
- 学校审核、派单、专家评阅和结果发布的角色页面改造；
- 真实消息发送、导出、支付或数据库持久化；
- 学生直接指定专家或查看专家身份。

页面必须用明确文案说明演示数据边界，不得把本地文件元数据或模拟进度描述成后端已完成。

## 3. 学生端信息架构

学生主导航保持：

1. 我的论文；
2. 评审结果与异议；
3. 消息通知。

论文编辑不是一级导航，由“新建论文”“继续编辑”“退回修改”进入。论文进度和详情通过工作台选中具体论文后查看，避免出现与论文记录无关的全局固定进度。

## 4. 学生可见阶段

学生端统一显示五个阶段，内部状态映射如下：

| 学生阶段 | 内部状态 | 学生看到的说明 |
|---|---|---|
| 材料准备 | `DRAFT` | 填写信息、上传材料或处理退回意见 |
| 学校审核 | `SUBMITTED`、`PREPARING`、`READY_FOR_DISPATCH` | 学校正在核验材料、匿名版或确认送审 |
| 送审评阅 | `UNDER_REVIEW` | 已进入专家评阅，不显示专家身份及内部派单细节 |
| 结果处理 | `RESULT_PROCESSING` | 评阅已返回，等待学校确认发布 |
| 已完成 | `COMPLETED` | 查看已发布结果并在允许范围内提交异议 |

`TERMINATED` 不进入五阶段进度，单独显示“流程已终止”及学校提供的公开原因。工作台详情时间线可以展示“已提交”“匿名核验中”“等待学校送出”等细分事件，但不向学生暴露平台队列名、专家任务状态和账务信息。

## 5. PAGE-002 我的论文

### 5.1 页面结构

- 提交资格与批次信息；
- 待我处理、送审中、已完成三个有效统计；
- 状态筛选和关键词搜索；
- 本人全部论文表格；
- 当前选中论文的五阶段进度；
- 论文详情抽屉，包含基本信息、材料、状态时间线、退回原因和允许动作。

表格行可点击。选中行后，进度和详情必须切换到该论文；不得继续使用固定主线论文数据。学校代传或批量导入记录正常出现在本人列表中，但学生只能查看，不需要二次确认，也不能修改学校提交的内容。

### 5.2 状态驱动动作

| 条件 | 动作 | 结果 |
|---|---|---|
| 本人自提草稿 | 继续编辑、删除草稿 | 进入编辑页，或二次确认后移除未提交草稿 |
| 被学校退回 | 查看退回原因、修改后重新提交 | 返回编辑页并保留上一版本数据 |
| 派单前 | 查看进度、撤回至草稿 | 二次确认后回到 `DRAFT`，保留提交和撤回记录 |
| 送审评阅中 | 查看进度、申请撤回 | 创建“等待学校处理”的撤回申请，不直接改变论文阶段 |
| 结果处理中 | 查看进度 | 不提供催促发布或提前查看结果 |
| 已完成 | 查看结果、提交异议 | 进入 PAGE-012 对应论文 |
| 学校代传/批量导入 | 查看详情 | 学生没有编辑和确认动作 |

所有动作完成后，表格状态、统计、进度、时间线和消息必须同时更新。

## 6. PAGE-003 论文编辑与上传

### 6.1 学籍和资格

页面顶部显示学校、学院、学号、姓名、培养层次、学位类型、导师、批次和截止时间。这些字段来自学校权威数据，在学生端只读；页面提供“信息有误请联系学校管理员”的说明，不提供直接修改入口。

### 6.2 可编辑字段

- 论文题目：必填；
- 摘要：必填，多行输入；
- 学科专业：必选，保存代码和名称；
- 关键词：建议 3—5 个，保存去空白、去重后的数组；
- 原始论文：必填；
- 匿名版论文：必填；
- 补充附件：选填，可多项。

### 6.3 专业选择器

专业选择器必须是浮层组件：

- 初始状态收起，即使当前没有选值也不自动展开；
- 点击控制框或按 Enter/Space 后，在控制框下方悬浮打开，不改变表单高度；
- 浮层顶部提供搜索框，支持代码、名称和别名匹配；
- 结果展示四位代码、名称以及“一级学科/专业学位类别”类型；
- 当前选项高亮，方向键移动，Enter 选择，Esc 或点击外部关闭；
- 结果区限制高度并独立滚动；靠近视口底部时允许向上展开；
- 空结果显示“未找到匹配专业，请检查代码或名称”，不允许自由文本提交；
- 浮层层级高于表单、粘性操作栏和普通卡片，低于确认对话框。

标签行文案固定为：

> 学科专业　按代码或名称搜索，请选择与论文研究内容最匹配的送审专业。

首版目录使用国务院学位委员会、教育部发布并自 2023 年起实施的《研究生教育学科专业目录（2022 年）》，同时包含一级学科和专业学位类别。数据保存为独立、带版本和来源信息的 JSON；学校/批次允许范围后续由后端过滤，当前演示可搜索完整目录。官方来源：[教育部通知](https://www.moe.gov.cn/srcsite/A22/moe_833/202209/t20220914_660828.html)及其[目录附件](https://www.moe.gov.cn/srcsite/a22/moe_833/202209/W020220914572994461110.pdf)。

### 6.4 关键词

标签行文案固定为：

> 关键词　输入后按 Enter 或分号生成标签，建议填写 3—5 个。

输入框下补充：

> 关键词用于辅助专家匹配，完全重复的词会自动合并。

Enter、中文/英文分号和输入框失焦均可提交当前词；空白词不生成标签；达到 5 个后停止新增并解释原因；每个 Tag 可以通过鼠标或键盘删除。

### 6.5 文件交互

原始版、匿名版和附件均提供选择、模拟进度、成功、失败、删除和重新选择状态。演示模式只保存文件名、大小、类型和模拟校验结果，不读取或上传论文正文。

匿名版区域必须持续提示不得包含姓名、学号、导师、致谢、页眉页脚、可识别文件名和文档元数据。选择明显包含姓名的演示文件名时，显示可操作的匿名风险提示，但不宣称完成正文检测。

### 6.6 保存和提交

- “保存草稿”立即保存并显示最后保存时间；
- 字段变化后显示“有未保存修改”；
- 离开页面前如存在未保存修改，弹出确认；
- “提交学校审核”先完成必填、专业目录、关键词数量和文件校验；
- 校验失败时滚动并聚焦首个错误；
- 校验通过后显示二次确认，确认后进入 `SUBMITTED` 并返回工作台；
- 重复点击不得产生重复提交。

## 7. PAGE-012 结果与异议

页面始终绑定具体论文。通过工作台进入时携带论文标识；从一级导航进入时，先选择一篇本人论文。

- 未发布：显示当前学生阶段、最近事件和“结果尚未由学校发布”；
- 已发布：显示总分、六个评分维度、结论、获准公开评语和发布时间；
- 专家始终以“专家 A”等匿名序号展示；
- 学校未批准公开的评语不得出现在学生投影中；
- 允许异议时提供理由、诉求和附件；提交前二次确认；
- 异议状态为“已提交、处理中、已办结”，不回退论文宏观阶段；
- 已存在未办结异议时禁止重复提交，并引导查看当前处理记录。

当前学校尚未提供统一异议截止期限，因此演示页不编造固定天数，只展示“是否允许提交”及学校规则说明。

## 8. 学生消息

以下学生动作或状态变化生成站内演示消息：

- 草稿保存失败；
- 论文提交成功；
- 学校退回材料；
- 论文进入送审评阅；
- 结果已经发布；
- 撤回申请状态变化；
- 异议状态变化。

消息支持单条已读、全部已读，并可跳转到对应论文、结果或异议详情。演示消息不发送短信或邮件。

## 9. 演示场景控制器

场景控制器只在显式配置 `VITE_DEMO_MODE=true` 时显示，与业务导航和业务按钮视觉隔离，并标明“仅用于演示，不代表学生拥有该操作权限”。是否显示不依赖开发或生产构建模式：甲方演示构建可以开启，任何未显式开启演示配置的环境都必须隐藏。

控制器提供：

- 切换主线论文到“草稿、学校退回、学校审核、送审评阅、结果处理、已完成”；
- 切换资格为“有效、暂停、已过期”；
- 切换文件校验为“成功、失败”；
- 一键恢复默认演示数据。

场景切换直接装载预定义且内部一致的快照，不逐步伪造跨角色动作。例如切换到“已完成”必须同时具备已发布结果、完成时间线和结果消息。关闭 `VITE_DEMO_MODE` 后不得渲染控制器入口，也不得通过普通学生路由调用快照切换动作。

## 10. 前端状态与持久化

学生页面只依赖一个 `StudentPortalService` 接口，不直接操作演示状态。接口负责论文列表、详情、草稿、提交、撤回、结果、异议、消息和演示快照；当前实现使用浏览器本地适配器，后续替换为 HTTP 适配器。

本地演示状态保存到带版本号的 `localStorage` 键。页面刷新和角色切换后保留状态；数据版本不兼容时自动恢复默认快照并给出一次性提示。演示文件只保存元数据，不把文件二进制写入本地存储。

## 11. 错误和空状态

- 加载失败：保留页面结构，说明失败原因并提供“重新加载”；
- 无提交资格：禁用新建和提交，显示学校返回的公开原因；
- 无论文：解释如何开始并提供“新建论文”；
- 专业目录加载失败：禁止提交，允许重试，不降级为自由文本；
- 保存失败：保留未保存输入并允许重试；
- 状态冲突：重新读取最新状态，解释操作为何不再可用；
- 无已发布结果：显示进度，不渲染空分数卡；
- 异议附件失败：保留理由文本，允许单独重试附件。

## 12. 响应式与可访问性

- 页面不设置全局最大宽度；
- 桌面表格在窄屏转换为论文卡片，不让整页横向滚动；
- 专业浮层宽度不超出视口，移动端改为底部弹层但保持相同搜索和选择语义；
- 所有操作支持键盘焦点，焦点样式可见；
- 对话框打开后管理焦点并支持 Esc 关闭；
- 状态不能只依靠颜色表达；
- 动画遵循 `prefers-reduced-motion`；
- 保存、提交和错误反馈使用可被辅助技术读取的状态区域。

## 13. 组件边界

- `StudentThesisWorkspace`：组合筛选、列表、进度和详情，不维护业务规则；
- `DisciplineCombobox`：只负责目录搜索、浮层定位、键盘交互和选择；
- `KeywordTagInput`：只负责标签输入、去重、数量限制和删除；
- `ThesisMaterialEditor`：组合只读学籍、论文信息和文件元数据；
- `StudentProgressTimeline`：把内部状态映射为五阶段与细分事件；
- `StudentResultAndObjection`：结果投影和异议表单；
- `DemoScenarioController`：只在演示环境装载一致快照；
- `StudentPortalService`：封装业务动作、状态校验和持久化。

组件不得各自复制状态判断；允许动作和状态转换统一由服务层产生。

## 14. 验收标准

1. 专业选择器默认收起，打开后不改变页面布局；支持代码/名称搜索、键盘选择、外部点击和 Esc 关闭。
2. 专业目录不再只有三个硬编码项，完整目录由带来源和版本的 JSON 提供。
3. 专业和关键词的操作说明与本规格文案一致。
4. 工作台切换论文后，进度、详情和动作同步切换。
5. 草稿保存、提交、派单前撤回、派单后撤回申请、查看结果和提交异议均产生可见状态变化。
6. 学生无法通过业务按钮直接推进学校、运营或专家动作，也无法看到专家身份。
7. 演示控制器可以加载六种主线论文快照，并明确标注演示权限边界。
8. 刷新后保留演示状态；一键重置恢复确定的默认数据。
9. 文件、目录、保存、状态冲突和异议附件失败均有可恢复反馈。
10. 390px 宽度下可完成编辑、专业选择、Tag 输入、提交、查看进度和提交异议，页面没有全局横向溢出。
11. 单元测试覆盖状态映射、允许动作、专业搜索、关键词规则和持久化迁移；组件测试覆盖主要点击路径；浏览器测试覆盖学生黄金路径和演示场景切换。

## 15. 后续角色衔接

学生端通过统一服务接口产出的 `SUBMITTED`、撤回申请和异议记录，是学校管理员端下一轮的输入。学校、百杰运营和专家端完成后，同一主线论文将通过各角色合法动作连续推进；届时演示控制器仍保留为现场容错工具，但不替代端到端演示。
