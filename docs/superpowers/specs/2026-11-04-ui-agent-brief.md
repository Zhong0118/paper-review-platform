# 百杰校审｜产品页面设计简报

**UI agent 从这里开始。** 2026-11-04，业务核对基线 `4686bd8`。这是一份新设计，未在真实平台实施。本文取代之前的“六角色图册”和“先改管理员学校表”施工顺序。设计范围由用户任务决定，旧页面只用于核对业务和权限。[打开可点击的原型](../../images/2026-11-04-review-desk.html)。

**设计题：同一篇论文到了我手上，我首先要知道什么？** 学校要判断“这份材料现在能不能送”；专家要同时看到“论文的证据和我的意见”；学生要读懂“发布的结论和需要改什么”。如果把三个页面的标题遮住，仍应能从首屏分清这三种工作。侧栏、表格和蓝色按钮都不是产品的主角。

## 一、十二种类型，分别如何处置

类型是设计师的工具，不是给用户看的十二个菜单。下表包含 **6 种页面模板、4 项合并呈现、1 个身份外壳、1 项暂缓**。模板可以复用在老路由上，不要求增加六个 URL。

| 用户提出的类型 | 首版决定 | 在盲审平台里怎样用；明确删什么 |
|---|---|---|
| 01 Landing／首页 | **合入登录** | 当前是学校邀请使用的业务系统。未登录者只需认出“百杰校审”、知道用途、找到平台账号入口。删独立宣传首页、轮播、客户数字和“立即体验”。未来有公开获客需求再分站 |
| 02 Dashboard／工作台 | **独立模板：优先办理** | 学校默认送审准备，运营默认待派队列。首屏给“当前待办 → 哪一条 → 下一步”，计数点开即对应清单。系统管理员直接进学校表；导师直接进结果；不为每个角色造一块驾驶舱 |
| 03 Table／数据列表 | **独立模板：比较和选择** | 学校、批次、成员、专家、论文队列是表。首列是用户认得的名称／匿名编号；每行一个主动作。保留列设置、键盘调序等已有能力。删除无效批量勾选、重复状态过滤、永远只有一页的分页 |
| 04 Detail／详情页 | **独立模板：一个对象** | 学校或论文的短详情用侧抽屉；需要深链的正式结果用完整阅读页。标题下只有版本、状态和对当前人有意义的字段。关闭回到原筛选和原行；不在对象下面平铺另一份全量列表 |
| 05 Form／表单 | **独立模板：一份草稿** | 短表单如新增管理员用对话框；论文编辑和专家评分用专注页。保存、校验、最终提交明确区分；不能代填意见。没有改动不打断离开；有未保存输入给返回编辑选项 |
| 06 Kanban／看板 | **暂缓** | 当前单篇单专家，由不同授权人触发状态转换。同一操作者需要的是筛选队列，不是自由拖拽。首版不做卡片墙或拖卡流转。将来有跨批排程需求可先验证只读分栏；审批仍走原命令 |
| 07 Analytics／图表 | **嵌入进度和队列** | 学校进度可看已发布结果的评分分布、任务状态；运营看已有派单／负荷投影。图旁给口径、分母、时间范围，无数据与未配置分开表示。只有能查询相同集合的图才可下钻。去掉预测、综合指数和无出处的环比、不增独立 BI 入口 |
| 08 Workflow／流程页 | **独立模板：一次交接** | 校方匿名核验、确认送出、运营派单或发布确认需要“对象 → 已有证据／阻断原因 → 下一步 → 操作后谁来办”。简单一步不要包装成四步向导；不做所有角色都看得到的全链路控制台 |
| 09 Settings／设置 | **合入所属业务** | 批次期限归该批次；开放学科、校内专业对照、检测词表归本校设置；全国官方目录归系统管理。可以有配置子页，不设跨角色的设置大全。官方目录更新、本校 CSV 发布、入驻学校开通三者不是一个“导入”按钮 |
| 10 Profile／个人中心 | **合入账户菜单** | 所有人右上同一入口 → 本人信息／退出登录。本人信息先只读显示真实姓名或用户名、角色、已知学校代码；移动端可整屏查看。专家业务档案不是这个人的登录信息。删除自助改角色、假邮箱、头像上传和个人动态 |
| 11 Auth／登录注册 | **独立模板：登录** | 品牌、平台账号、密码、登录、明确错误和重试。真实试点不开放注册；不提供 demo 快捷身份切换、无后端的 SSO、邀请码注册或忘记密码假流程。对访问受保护链接的用户沿用现有授权与跳转语义 |
| 12 Portal／用户门户 | **共用身份外壳** | 只负责“我是谁、我可以去哪、怎么返回”。六角色同一顶栏和左侧导航位置，按当前授权缩减项目；编辑和评阅默认收起。没有独立门户首页，不做一个只有六个角色大按钮的入口 |

## 二、六个人从哪里进，到哪里结束

这里的“老师”要拆开：学校审核员处理本校业务；导师只读本人指导学生的已发布结果。系统管理员管学校与账号，平台运营管派单和审批；同一外观不意味着兼得权限。下面是首版导航信息架构；括号中为页内能力，不拆成全局菜单。

| 身份 | 首屏／页型 | 侧栏目的地 | 一条可以现场验证的路径 |
|---|---|---|---|
| 学校审核 | 送审准备／工作台 + 表 | 办送审：送审准备、评审进度、结果处理、异议处理。管本校：批次与规则、成员与资格、学科与专业、材料检测词表 | 找到一篇待核验论文 → 对照原稿／匿名稿与发现 → 按实际状态通过或退回 → 可送时确认。另从结果处理核对发布版本；学校不见专家姓名 |
| 平台运营 | 派单工作台／工作台 + 流程 | 派单工作台、专家库、更正审批；延期审批在派单工作台内 | 选论文 → 比较候选及回避原因、负荷 → 确认派单。不得把业务操作扩成读取原稿或正式评分 |
| 系统管理 | 学校管理／表 | 学校管理、官方基础目录 | 搜索入驻学校 → 单校管理员表 → 管理指定账号。官方目录独立预览差异、确认入库；更新名录不会开通学校 |
| 学生 | 我的论文／个人列表 | 我的论文、结果与异议 | 接着编一份草稿 → 补齐材料并提交。学校发布后从结果与异议读正式结论及匿名意见，按权限登记异议 |
| 专家 | 我的任务／任务列表 | 我的任务 | 在当前状态分组找到本人邀请 → 接单 → 仅阅读获准匿名稿、填评语并提交。延期、更正附属于任务；提交后的正式版本只读 |
| 导师 | 学生评审结果／阅读详情 + 选择器 | 学生评审结果 | 选受本人指导且有权查看的论文 → 看发布版本及意见；不显示其他学生、草稿或专家实名。不为只有一个目的地的身份填充菜单 |

## 三、三张必须从白纸设计的屏幕

先打开原型，用顶部的**设计图册控件**对照同一论文在三个不同时点的虚构样本；此控件绝不移入产品。原型用来判断首屏信息顺序，不是真实 API 的验收。

| 场景 | 首屏和主要交互 | 不能做成什么 |
|---|---|---|
| **学校：清单 → 核验详情** | 看得到论文题目、状态、学科，以及为什么该办；用状态或关键词缩小清单。选中一篇时在详情里看版本、检查证据、下一步；不同时显示所有论文的材料和按钮。真实写操作要带版本、权限和后果说明 | 四张 KPI 卡在上、核验对象在两屏之外；把命中敏感词等同于系统自动审批 |
| **专家：读匿名稿 → 写意见** | 首屏同时出现论文内容和“主要问题”输入，留足连续阅读宽度；任务匿名号和保存状态常在视线内。宽屏分栏，窄屏材料／评阅表切换；同任务切面板保留输入，切任务清空旧数据。评估规则、确认及六维分值按后端 | 把学术阅读挤在后台数据表里；模板生成评语；显露作者、学校、原文，或用过期令牌取回旧材料 |
| **学生：读发布件** | 第一眼知道是哪篇、第几版、结论如何。然后是“主要问题／修改建议”的完整段落，其次才是分项评分；异议在该份结果的操作区。未发布、未授权不能渲染此样本或暗示结果存在 | 大号仪表盘代替文字反馈；把导师只读界面也装上学生的异议操作 |

**视觉方向：像高校办件台、评阅桌和发布件，而不是一套首页皮肤。** 办件台紧凑对齐，评阅桌把空间给两种并行任务，发布件用纸张宽度和段落留白。三者共享小字号元信息、学术蓝和行动用语，不强迫使用同样多的卡片。

- **框架与版心**：普通宽屏 ≥1200px 用文字侧栏，管理端约 216px，个人端约 176–184px；用户可收起。专注页默认收起，保留返回上级与账户。768–1199px 默认收栏；手机以带文字菜单打开抽屉。评阅净宽不足 960px 切为一块面板；结果正文约 36–42 个汉字一行。桌面 1366×768 第一屏能看到第一条可办理的业务数据。
- **版式与质感**：白纸、墨色文字、淡灰蓝分隔、学术蓝 `#1B4F8A` 作主动作，警示赭色只用在需要人工处理处，红色保留给危险与阻断。界面用苹方／微软雅黑，论文题名和正式发布件用宋体回退；正文 14–16px、长评语行高约 1.7。沿用现有开源图标，不用装饰性英文编号、印章、渐变大屏、无限页面树或 emoji。
- **行为**：列表只给一个高频主动作；危险操作进入对象详情再确认。区分无记录、筛选无匹配、无权限、未配置、失败和有未保存输入。表头具备语义；小屏表内滚动。菜单、筛选、列设置、抽屉支持键盘，关闭归还焦点。控件进出约 150–200ms，无障碍减少动效时立即切换。保存失败不丢输入。
- **借鉴有边界**：[Notion 侧栏](https://www.notion.com/help/navigate-with-the-sidebar)借位置稳定和可收起；[Notion 看板](https://www.notion.com/help/boards)是按属性组织的一个视图，不是本平台的授权模型。[shadcn/ui](https://ui.shadcn.com/docs/components/base/sidebar)借组合方式，不换 React 栈；[Ant Design 数据列表](https://ant.design/docs/spec/data-list-cn/)借表、详情与操作的分层。参考 Screenrove 的 [Todoist 清单](https://screenrove.com/todoist/product/todoist-product-project-list)和 [Overleaf 编辑器](https://screenrove.com/overleaf/product/overleaf-product-editor)，分别解决任务筛选和读写并行，不照搬可分享、拖卡或协作功能。

## 四、哪些可以丢，哪些必须留

**丢掉**旧页面布局、默认横排导航、从上到下串联所有模块的长页、为每个角色复制的欢迎首页、无意义的统计卡、展示 demo 人名／费率的占位页、费用／通知等未接通菜单、重复筛选和“本页功能介绍”。共有能力优先在一处解决：本人信息和退出在公共顶栏，列设置在对应表，日期范围只在已有范围查询的业务使用。

**保留**真实 API、角色和数据边界、原深链及任务 ID、PDF 的受控读取、正式结果的版本、已有状态转换、日期口径、列显隐／拖动／键盘排序、表单与回归测试。旧组件可替换；不要批量删页或用 mock 接管真实路由。已有能力的入口被移走时必须列清新去处，不能因视觉简化而丢了退回、延期、更正或异议。发现必须改接口或授权才成立的设想，列入待决，不画成已实现。

## 五、给 UI agent 的任务单

| 顺序 | 交付 | 通过标准 |
|---|---|---|
| A：先验设计 | 学校清单与详情、专家读写、学生发布件：桌面 + 手机的可点击稿；另附“删除／合并／迁移去向”清单。不先铺六套侧栏 | 学校审核员不翻两屏即可打开待核验项；专家从读材料切回原输入；学生不用展开评分就能找到修改建议。三人都能解释当前对象、阶段和下一步 |
| B：第一条真实竖切 | 复用 Vue 和现有控件，做共用账户／导航 + 学校准备列表至单篇核验；先记录现有行为再替换展示层 | 在独立场景验证核验及权限、错误重试、返回仍保留筛选与焦点。六角色可查看本人信息并真正退出；账号 A 退出后 B 不见 A 的缓存与论文。到此停下给用户实测 |
| C：移植其余办件页 | 学校管理表与目录、学校配置、运营派单与专家库、结果发布与异议；覆盖原路由、空态与危险操作 | 原有可办操作都有安全新入口；学校不见专家实名、运营不取超范围字段、系统管理员不读正文。搜索／范围口径可解释，列设置不退化 |
| D：个人门户与交付 | 学生稿件、专家专注评阅、学生／导师结果。收口清理无引用旧展示，保留账户、路由与恢复测试 | 用非 demo 浏览器走提交→核验→派单→评阅→发布→结果与退出；1366／1024／390px、键盘与未保存输入检查；定向测试、前端全量、类型检查、真实模式构建。分清原型图、真实界面和未运行项 |

实际执行先读 [AGENTS.md](../../../AGENTS.md)、[CURRENT](../../CURRENT.md)、[真实角色菜单](../../../frontend/src/router/menus.ts)、[隔离启动说明](../../../README.md#隔离验收环境)。旧版的[接口与页面核对记录](2026-11-04-agent-ui-design-guide.md)只在需要查学校字段、目录导入、账户或旧路由时参考。用本机 5433/paper_review_test 独立 schema；不复用或停止用户正在试用的前后端。不要把设计图的数值、姓名或流程状态写入真实前端。

**可直接复制给 UI agent：**

> 按本文 12 类取舍，从白纸排版。先交付 A 的三张关键场景及桌面、手机对照，可复用本文原型作比较，但不要沿用旧角色图册的布局。标明每个对象、主动作、数据来源、删除项去向与状态边界；不改后端，不删整站，不提交或部署。先让用户验设计；确定后才按 B 接真实业务，首条竖切通过后再扩面。不要把十二类做成十二个菜单。
