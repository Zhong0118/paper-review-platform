# 7B-1 专家真实阅读与任务路由

依据 CURRENT、审查 B3/B6 和用户已确认的后续修复计划；只修既有专家任务/评阅流程。

- 真实工作台必须指定 query task_id，从本人列表精确匹配，不回退到第一项。列表继续评阅/查看及接单成功均携带任务 id。缺参、非本人、拒绝/撤销/未接任务显示明确错误和任务列表入口，不显示其他任务或可编辑表单。
- 路由切换重置表单、对话框和材料，旧请求晚到不能覆盖新任务；保存/提交捕获当前 id，完成后的提示与刷新不能污染另一个任务。表单按任务重建，取消旧自动保存定时器。
- IN_REVIEW 使用现有 materials 与带 Bearer 的文件 GET。materials 只给当前有效轮次、当前论文版本、已完成匿名 PDF；展示安全文件名“匿名论文.pdf”，不暴露作者、原文或原始上传名。复用读取权限与审计。
- 浏览器原生 PDF 阅读器通过内存 Blob URL 展示。加载、失败/重试、无法内嵌时新窗口打开均有入口；任务切换/卸载释放 Blob URL，旧下载晚到也不能出现。文件不写 localStorage。原生阅读器可能允许保存/打印，不标榜“禁止下载”。
- 真实模式不挂载演示文档组件，不展示固定 86 页、固定摘要或虚构校验标签；不引入 PDF.js/OCR。
- 列表返回 IN_REVIEW 的 CONTINUE_REVIEW 和 SUBMITTED 的 VIEW_SUBMITTED。SUBMITTED 仅显示本人正式意见（新增 GET /expert/tasks/{id}/result，来自当前 ReviewResultVersion），禁止编辑、不再请求论文文件。不用可能落后的草稿冒充最终意见。更正申请未接入，真实模式不显示虚假入口。
- 演示模式保持既有流程，不向 scenarioService 添加业务。无数据库迁移、不增加结果更正功能。
- 验证：多任务精确选择、无参/未知/不可评阅拒绝、路由竞态、草稿/正式意见正确、PDF 失败重试/资源释放、任务列表路由；后端本人/他人、提交前后、失效轮次材料边界；全套前后端测试与构建。
