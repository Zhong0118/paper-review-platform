# 20 校内专业代码映射 · 已批准设计
状态：三条决策已由用户批准。[执行计划](../plans/2026-11-03-school-program-code-mapping.md)。目标是让学生选到本校实际培养专业，同时保留全国官方学科口径，不把校内代码写进后端或当作全国代码。
示例（仅作交互说明，非真实目录）：学校 A 的“校码 X017 / 智能计算方向”映射到已导入的官方条目。学校 B 即使用同一码也完全独立；不按名称相似度自动决定映射。

## 谁维护、使用什么来源
学校审核员仅能维护本校映射。国家目录沿用现有经校验的官方来源；校内条目必须来自本校正式发布的研究生培养/招生专业目录或学校正式提供的表，记录文件名或官方链接、目录年份、来源版本、确认人和时间。全国高校名录不提供校内专业映射，不从第三方列表推断二级学科。若没有正式表，继续用现有官方选择器。
第一版支持一个学校一份 CSV 模板；校内代码按字符串保存（保留前导零），同时提供校内名称、官方代码、年份和来源。预览显示新增、变更和错误行；未知官方代码、同年度同校重复代码、歧义或无来源整批不生效。未出现在新文件内不自动停用。

## 数据与选择流程
- 学校、学年、校码共同确定条目；一个年度版本的校码只指向一个官方类别，允许多个校码落在同一官方类别。跨学院复用相同校码、方向多对多等先列入待核对，不自动择一。
- 目录版本先预览，再以预览所据版本确认发布；并发变化要求重做预览。生效后不覆盖已引用的条目。批次明确绑定学校选定的目录版本，不根据当前日期自动换届。只在本校既有开放学科之内提供新选择，不重新打开关闭的官方类别。
- 无绑定批次保持现行“官方代码 / 名称”单选。有绑定时，学生可搜校码、校名、官方代码；选择项同时显示两套名称。前端提交所选条目标识；后端按身份、原批次和绑定版本校验归属并解析官方代码，拒绝串校/跨年度/伪造组合。
- 新稿同时保存校内条目版本和官方代码快照；历史论文不猜测回填，不因改名、重映射或停用改写结果。既有未带映射的草稿继续走原路径，主动重选才补快照。档案、导出历史回读快照，不依赖最新名录。
- 学校和学生可见双口径；专家候选筛选沿用论文的官方学科。校码、学院或学校名可能破盲，不进入专家材料、PDF元信息和专家评阅页面。扩展学校侧查询和行级权限时仅允许本校维护，不能由客户端传租户决定范围。

## 建议的首版与验收
只做导入预览/确认、批次绑定和学生单选；不做爬取、模糊自动匹配、复杂院系树、自动改派或历史回填。
1. 两校同码异名互不可见，前导零不丢；错码、重复行整批不生效。
2. 绑定后可搜双口径；停用或关闭时给出可操作提示，旧结果仍显示当时名称；未绑定批次和已有草稿行为不变。
3. 更换年度目录不改变在途批次或已发布论文，跨校/跨版条目不能提交，旧目录预览不能覆盖新配置。
4. 专家只能看到原本获准的字段；不能从页面、API、文件和导出得知学校来源。

## 已批准的三个决定
采用 **目录版本随批次固定**、**第一版每条校码只对应一个官方类别**、**不强迫存量草稿重新选择**。若实际校方目录在同年跨学院复用代码，需先决定是否把院系加入识别键。首所学校接入时，用校方提供的小份表头和脱敏样例核对这三点；仓库没有真实校方映射表。
