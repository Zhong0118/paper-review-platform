# 7C-3 修复派单与发布一致性

依据整体审查 A3/B2/B9，用户要求先修已有 bug。

- 当前仅支持单专家。轮次内 INVITED/IN_REVIEW/SUBMITTED 占用席位，REJECTED/CANCELLED 不占；不能向另一专家绕过人数限制。派单在论文锁下检查。
- 候选与实际派单共用回避判断（展示名与导师姓名关系、档案 SUPERVISOR_NAME），实际命中返回 409。
- 评阅写入锁顺序统一为论文→任务，与派单/发布协调。最终提交只允许当前版本、有效轮次、UNDER_REVIEW，并且轮次恰有当前这一份占位任务；旧异常多任务不自动选一个通过。
- 汇总保存任务集合。发布前验证集合恰好一份，任务和正式结果属于当前轮次，分数与汇总一致且无额外占位任务。发布后学校/学生/导师均按该已记录集合读取，不动态并入新任务。
- 现行没有合法修改正式结果的接口（7C-1 已锁定），因此复用 summary.result_task_ids 固定集合，不新增 JSON 快照或迁移。不声称防止绕过应用直接改数据库；未来更正功能必须另立不可变版本发布规格。
- 历史数据若缺结果、集合不一致或超额占位，发布拒绝，不猜测修正历史分数。
- 全拒绝时重新计为等待，正式结果已提交不计等待；保留 rejected 统计及任务历史。
- 未做批次规则可配置化，现行单专家常量仍是开发切片限制。无前端功能扩展。

验证：两名合格专家并发只成功一个、档案回避 API、拒绝后另派、等待统计、晚到结果拒绝、发布集合固定、历史不一致拒绝发布、原有回归。使用独立 Postgres 5433/paper_review_test。

关联修复：接受/拒绝任务也取得论文→任务锁并刷新状态，防止延迟的 INVITED 请求覆盖最终提交后的状态。
