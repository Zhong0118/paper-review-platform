# UI 重设计 U3：学校办理收尾、学校设置、平台资源与系统管理原型

日期：2026-11-05。依据：[U0 功能地图](2026-11-04-ui-redesign-u0-function-map.md) §2.3–2.6、§3、§4；[U2 计划](2026-11-04-ui-redesign-u2-plan.md)。

U3 只做可点击原型，过程与 U1 相同：原型 → 用户验收 → 再按页接线（U4）。本轮不改真实页面、路由、接口和权限。

## 1. 范围

| 编号 | 原型 | 路由 | 工作空间 |
|---|---|---|---|
| P09 | 学校结果处理（发布、更正确认、导出） | `/prototype/results` | 处理 |
| P11 | 学校异议处理 | `/prototype/objections` | 处理 |
| P12a | 批次与规则 | `/prototype/settings/batches` | 处理（学校设置组） |
| P12b | 成员与资格 | `/prototype/settings/members` | 处理（学校设置组） |
| P12c | 学科与专业 | `/prototype/settings/disciplines` | 处理（学校设置组） |
| P12d | 检测词表 | `/prototype/settings/terms` | 处理（学校设置组） |
| P13a | 专家库（含 CSV 导入） | `/prototype/experts` | 处理 |
| P13b | 更正审批 | `/prototype/corrections` | 处理 |
| P14a | 学校管理（含新增学校、学校管理员） | `/prototype/system` | 处理 |
| P14b | 官方基础目录 | `/prototype/system/catalog` | 处理 |

不在本轮：P07 专家任务列表、`/school/progress` 评审进度、登录页。三者是否进入 U3 由用户另定；侧栏里它们保持“未链接”。

## 2. 共同约定

- 只用虚构数据，不导入 `src/api`、`src/stores`，不发请求。路由只在 DEV 注册（沿用 `src/prototypes/routes.ts`）。
- 每页右下原型控制可切换 U0 §3 表中该页的全部状态，并同步到 `?state=`。
- 列表页统一为“清单｜对象”两栏：左侧视图页签带计数（只算已加载集合，页面写明口径），右侧是对象详情；窄于 900px 时先看清单，点开后进入对象，顶部有“‹ 返回清单”。
- 危险动作（发布、暂停学校、停用账号、归档批次、不予确认更正）用真模态确认，确认文案说清对谁有什么影响。
- 409：保留用户已经输入的内容，读回服务端版本，说明哪里变了，再让用户决定。原型用“版本冲突”状态演示。
- 密码只在输入框里出现，提交后不回显、不进截图；原型里永远是空输入框。
- 盲审口径（U0 §4）：学校只看到专家别名 E-001；平台更正审批只看申请信息，不看学校专属的更正前后对照；系统管理员不读论文正文。

## 3. 各页

### P09 学校结果处理

- 清单视图：待发布、更正待确认、已发布、全部。行显示题目、学生、结论或状态。
- 对象区按“将公开的内容”排序：结论与总分 → 每位专家（别名）的建议、总体评价、主要问题、修改建议、分项评分 → 提交时复核提示（只列提示代码与数量，不改结论）。
- 明确列出“不会公开”的内容：专家身份、主要优点、分项评价、完整评语。
- 发布：主动作“发布结果”，模态内再次列出学生与导师将看到的内容；发布成功后读回发布快照，显示“已发布”。
- 已发布：主动作消失，次要动作“导出评阅书”。
- 更正待确认：对象内分区，原生效版本与待确认更正并排对照；“确认更正”会自动追加一条发布记录，无需再次发布。确认与不予确认都要填写原因（接口 `reason` 必填）。
- 状态：待发布、首次加载、范围内无论文、加载失败、评阅未齐（不能发布）、版本冲突（结果在发布前变化）、发布确认、已发布、更正待确认、不予确认确认框。

### P11 学校异议处理

- 清单视图：待处理（SUBMITTED）、处理中（PROCESSING）、已办结（RESOLVED）。
- 对象区：学生的异议理由与诉求原文、论文题目、学生，附“查看发布结果”链接到 P09 对应论文。
- 待处理只有“开始处理”；处理中出现办结表单：办理渠道（线上/线下，必选）＋结论（必填，学生可见）。办结前确认。
- 已办结只读，显示渠道与结论。
- 状态：有待处理、首次加载、没有异议、加载失败、处理中（办结表单）、办结确认、已办结。

### P12a 批次与规则

- 清单：批次（状态 草稿/开放/截止收件/已归档）。对象区分区：基本信息（名称、代码、起止日期，可编辑）、生命周期（按 `allowed_actions` 出现 开放/截止收件/归档）、期限（接单天数、评阅天数，可留空表示未配置）、校内专业目录版本（固定到某个已发布版本）、收尾核对（未发布、未结异议、待确认更正三组，链接到 P09/P11 的原对象）、评审规则（只读侧栏）。
- 409：保留编辑中的字段，显示服务端当前值，用户选择“用我的修改覆盖”或“放弃我的修改”。
- 期限只在草稿与开放状态可改，修改只影响之后派出的任务；未配置时派出的任务没有截止日。
- 状态：正常、首次加载、还没有批次、加载失败、草稿批次（期限未配置）、版本冲突、截止收件确认、归档确认、新建批次。

### P12b 成员与资格

- 清单：学生 / 导师 / 全部，搜索姓名、学号或工号；停用账号显示“已停用”。
- 对象区：账号与联系方式（可编辑）、账号状态（启用/停用，停用需确认）、重置密码（输入新密码两次，提交后不回显）、送审资格（仅学生：建立/暂停/恢复；暂停只影响新建论文，不影响已有草稿继续办理）。
- 新建成员：类型、姓名、学号/工号、账号、初始密码（至少 12 位，与后端一致）。
- 状态：正常、首次加载、还没有成员、筛选无匹配、加载失败、资格已暂停（有草稿）、尚未建立资格、版本冲突、停用确认、重置密码、新建成员、成员不可见（已被移出本校）。

### P12c 学科与专业

- 两个分区页签：开放学科、校内专业对照。
- 开放学科：按门类分组的官方学科多选；未设置时说明“学生可以选择全部启用的官方学科”；保存带版本。
- 校内专业对照：已发布版本列表；导入 CSV → 预览（新增/变更/保留/错误）→ 确认发布。预览页醒目写“预览未写入”；有错误时不能发布。
- 状态：正常、首次加载、未设置开放学科、加载失败、版本冲突、导入预览未写入、预览有错误、发布确认。

### P12d 检测词表

- 一张可编辑表：词、严重程度（警告/阻断）、说明；增删行；保存带版本。
- 保存状态常驻（未保存的修改 N 处）。
- 版本冲突：保留本地修改，列出对方已保存的差异，用户选择合并方式。
- 状态：正常、首次加载、词表为空、加载失败、有未保存修改、版本冲突。

### P13a 专家库

- 清单：可指派 / 待审核 / 不可派 / 全部，筛选学科、搜索姓名与单位。
- 对象区三个独立分区，对应三种“不可用”：资格审核（待审核/已通过/未通过）、服务状态（可接单/暂停服务）、回避关系（回避学校、回避导师姓名）。三者各自修改、各自说明，不合成一个“不可用”。
- 档案信息与来源（来源链接、核对日期）可编辑，版本冲突时保留输入。
- 资格通过/不通过、暂停/恢复服务都要填写原因（接口 `reason` 必填）。
- 导入档案：只更新已有专家的档案字段（按账号精确匹配），不新建账号，不改资格、服务状态与回避关系。上传 CSV → 预览（逐字段 现在/导入后、逐行错误、10 分钟有效期）→ 应用。任何一行有错，整份预览不能应用；过期或期间档案变化（失效候选）整批不更新，只能重新上传。
- 状态：正常、首次加载、还没有专家、筛选无匹配、加载失败、资格待审核、本人暂停服务、版本冲突、暂停服务确认、导入预览、导入预览有错误、导入预览已过期。

### P13b 更正审批

- 清单：待审批（REQUESTED）、已处理、全部。
- 对象区只显示申请信息：专家、任务、论文（匿名题目）、申请理由、申请时间、历史备注；不显示学校专属的更正前后对照。
- 批准 / 驳回都要填写原因（接口 `reason` 必填，专家可见）；批准后专家起草，再交学校确认。进度条只读显示 申请 → 批准 → 提交更正稿 → 学校确认。
- 状态：有待审批、首次加载、没有更正申请、加载失败、批准确认、驳回确认、已被他人处理、已处理（待学校确认）。

### P14a 学校管理

- 表格：学校代码、名称、根组织、学校管理员人数、状态、创建日期。点行打开学校详情。
- 新增学校：先检索官方院校（名称须与官方名录一致），再填学校代码（2–32 位小写字母、数字、短横线）、根组织编号与名称、首位学校管理员（姓名、账号、初始密码至少 12 位）。学校代码重复（409）时保留输入、标出代码，并给出已使用该代码的学校入口。
- 学校详情：基本信息、暂停/恢复（暂停二次确认：该校全部会话立即撤销，恢复前无法登录）、学校管理员列表（新增、启停、重置密码）。
- 系统管理员不读论文正文，页面没有任何论文入口。
- 状态：正常、首次加载、还没有学校、筛选无匹配、加载失败、暂停确认、新增学校、重复学校。

### P14b 官方基础目录

- 独立目的地。现行接口不需要上传：服务端读取内置官方来源快照与库内目录比较，返回学科与院校的新增/变更/不变计数、来源与指纹；不返回逐条变化，原型只展示计数。
- 确认导入带指纹；指纹不符（他人先导入或来源快照已变）时整批不写入，只能重新预览。
- 状态：尚未预览、正在生成预览、预览失败、预览未写入、导入确认、预览已过期、已导入。

## 4. 导航

- 学校侧栏：结果处理、异议处理与四个设置项接到上表路由；评审进度仍未链接。
- 平台侧栏：专家库、更正审批接通。
- 新增系统管理侧栏：学校管理、官方基础目录。
- 原型索引追加 U3 各组及其状态直达链接。

## 5. 验收

- `vue-tsc`、vitest 两种模式、生产构建不含原型代码。
- 浏览器 1440×900、1366×768、390×844 逐页检查：无横向滚动、主动作可见、模态居中可用键盘关闭。
- 用户逐页验收后，再写 U4 接线计划。

### 5.1 本轮结果（2026-11-05，未提交）

- `vue-tsc` 通过；vitest 真实/演示两种模式各 87 个文件 672 项通过；生产构建不含原型代码（唯一命中“官方基础目录”的是现有 `TenantPermissionsPage` 自己的标题）。
- 浏览器：10 个原型在 1440×900、1366×768 逐页查看；390×844 下 19 个页面/状态脚本检查均无横向溢出，控制台无错误与 Vue 警告。
- 走查中修正：原型 `ConfirmDialog` 与正式组件同样被 Tailwind preflight 去掉 margin，已加 `margin: auto`（U1 原型的对话框一并修好）；窄屏更正对照表改为逐项上下排列；专家库三个分区在 1440 下改为两列＋回避关系独占一行；词表窄屏行内把严重程度与删除放在同一行。
- 新增共用件：`kit/MasterDetail.vue`（清单｜对象两栏，窄屏切换）、`kit/useNarrow.ts`、`kit/desk.css`（U3 共用样式，只作用于 `.ws`）、`data/u3.ts`（虚构数据）；`data/nav.ts` 接通学校、平台侧栏并新增系统管理侧栏。

## 6. 对照后端核实的口径（2026-11-05）

建原型时逐项读了后端，以下与最初设想不同，原型已按后端修正：

| 项 | 后端事实 | 位置 |
|---|---|---|
| 密码长度 | 学校成员、学校管理员、专家初始密码均至少 12 位 | `user/schema.py:13,31`、`expert/schema.py:98` |
| 更正的每个决定都要原因 | 平台批准/驳回、学校确认/不予确认都要求非空 `reason` | `review/correction_router.py` `DecisionBody`、`SchoolBody` |
| 专家资格与服务状态变更要原因 | `VersionReason.reason` 必填 | `expert/schema.py` |
| 专家 CSV 导入 | 只匹配已有账号、只改档案字段；任一行出错整份 INVALID；10 分钟过期；应用时任一专家版本/资格/服务状态变化整批 409 | `expert/import_service.py` |
| 官方目录导入 | 无上传，读内置来源快照；只返回计数与指纹 | `api/catalogs.ts`、`tenant/catalog_service.py` |
| 开放学科未设置 | `configured=false` 时不限制，学生可选全部启用的官方学科 | `tenant/catalog_service.py` `require_school_discipline` |
| 暂停学校 | 撤销该校全部会话；登录要求学校 ACTIVE | `tenant/service.py:136`、`auth/service.py:110` |
| 批次期限 | 只在 DRAFT/OPEN 可改；未配置则任务没有截止字段 | `dispatch/deadlines.py` |

仍需在接线前核对：更换批次专业目录版本对已建论文的影响；官方目录变更对已有学校设置的影响；词表修改后已有检测报告是否重算；异议需要专家复核时的系统内路径（目前没有）。
