# 受控试点交付：任务规划边界

本文件规定后续任务如何拆分和验收，不等于已经确认了学校的试点合同或生产部署方案。

## 已确认基线

- 当前交付为多校隔离背景下的单篇、单专家、平台账密垂直主链。
- 已登记审查问题 18/18 已处理；最近后端 141 passed（3 warnings）、前端 405 passed（54 files），类型/真实模式构建通过。仅作为既有证据，接手方需核对对应工作树。
- 普通 Chrome 已验证真实匿名 PDF 正文；完整多角色、跨浏览器及复杂材料验收仍有缺口。
- RLS 未实现，上真实数据前必须完成。生产认证、私有存储、恢复演练等必须有证据，不能由测试数量替代。

## 可立即执行的范围

保护并核验当前工作树、建立可复现自动化检查、建立隔离多角色验收入口。这三项不需要先决定费用、多专家规则、SSO 或学校合同。

## 试点候选范围（待 T04 核实）

建议先限定学校、批次、单专家流程、平台账号。学校是否接受该范围、是否必须多专家/SSO/批量导入/收费、首批容量和部署环境均未确认。不得把建议写成已承诺要求，也不得为了尽快上线删除必要能力。

## 全局约束

- 先规格、再失败测试、再最小实现；一次执行一项，验收后更新状态。
- 不改 docs/99_原始材料/；不向 frontend/src/demo/scenarioService.ts 添加业务。
- tenant_id 来自 token；theses.stage 仅通过 workflow.transition 修改；学校不见专家姓名，专家不见作者/原文。
- 测试用独立 Postgres 5433 / paper_review_test 和临时 schema；禁止指向其他项目 5432、生产库或开发业务表。
- 保留现有工作树全部修复；没有授权不 reset/clean、推送、合并或部署。
- 模型选择是工作分配建议；强模型也必须跑测试并接受审查。
