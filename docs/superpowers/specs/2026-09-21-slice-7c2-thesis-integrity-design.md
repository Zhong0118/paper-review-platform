# 7C-2：修复论文冻结、草稿删除和待送审撤回

依据整体审查 A2/A6、切片 0+1 派单前撤回规则。用户授权继续先修已有 bug。

- PATCH、提交、撤回、删除使用同一论文行锁并刷新状态；读当前版本时刷新已缓存对象。提交先胜则 PATCH 拒绝；PATCH 先胜则提交冻结最新内容。
- 从未提交的 DRAFT 可删除：先解除版本文件引用与上传版本引用，清除 current_version_id，再删除草稿版本和论文。保留文件对象/物理字节、创建/删除审计；旧上传不再可写。已有 submit 事件的论文，即使撤回到 DRAFT 也禁止删除。不开物理存储清理功能，不新增数据库字段。
- READY_FOR_DISPATCH 允许 withdraw 回 DRAFT，取消本版本 CREATED 轮次并保留其历史，新建可编辑版本；已派单不得通过此入口撤回。
- 确认送出与派单也在同一论文锁下刷新状态。撤回先胜则旧确认/派单失败；派单先胜则撤回失败。重新审核后确认送出创建 round_no 递增且绑定当前版本的新轮次；相同版本重复确认沿用有效轮次。
- 派单不得使用取消或旧版本轮次。结果读取选择当前版本轮次，避免重新送审后读到第一次已取消的轮次。发布快照、人数/回避规则、文件读取授权等剩余缺陷留待后续。
- 权限继续由 token 与论文所有权控制；阶段只能 workflow.transition 写入。无前端功能扩展和数据库迁移。

验证：纯草稿带文件删除/重新创建、他人不可删、提交后撤回不可删；独立会话旧对象和真实锁等待（PATCH/submit、delete/submit、withdraw/assign 双顺序）；确认后撤回、重提后必须重新确认、新轮次/旧文件历史、第二轮结果读取。测试仅用独立 Postgres 5433/paper_review_test。

补充：学校进度列表只统计当前版本的有效轮次，取消的历史轮次保留在数据库中，不重复进入当前列表或计数。
