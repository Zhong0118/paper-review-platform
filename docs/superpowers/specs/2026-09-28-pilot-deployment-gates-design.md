## 输入记录

执行者必须在受限运行环境得到：主机/容器运行方式与负责人、域名/TLS终止位置、PostgreSQL版本及三个应用登录的管理方式、私有存储绝对目录与持久卷、备份位置/加密/访问权限/保留期限、RPO/RTO数值、管理员身份和安全发放/恢复渠道、试点时间、数据来源/授权/保留与删除规则、部署与恢复操作窗口及用户明确授权。文档只保存变量名和引用，不保存密码/真实论文。

缺少某字段时仅相应门禁 BLOCKED，其余本地任务继续。选择容器或进程服务后才生成具体部署配置，不提前提供带默认口令可误运行的万能 docker-compose。

## T09-B 运行与认证

- 前端静态构建 VITE_DEMO_MODE=false，通过同源 HTTPS `/api` 代理到后端；后端与数据库不直接公网暴露，反向代理禁止记录 query/Authorization/Cookie，禁缓存认证及私有文件响应，验证错误/重定向日志也不含 token。
- 后端 production 配置通过 T09-A；JWT 随机生成并受限保管。迁移/业务/认证分别用不同登录，运行进程只得到业务与认证连接；migration 登录只在离线迁移任务使用。当前 Settings production 校验要求提供 migration URL；在实际部署前必须设计并测试“运行模式不需要迁移凭据”的配置拆分，不能把 owner 密码长期注入 API 来满足校验。这属于 B1 同片实现并有负向测试。
- 应用启动禁止演示 seed，首次系统/平台管理员由离线维护命令创建；专家账户由 T07 页面创建。维护命令范围仅 bootstrap global system_admin/platform_reviewer 与 reset-global-password，不写论文/评分/学校身份；离线人工核验身份、停应用后运行，重置密码同时 auth_version+1、撤销 refresh 会话、记录脱敏审计。
- 维护凭据为专用离线 DBA/维护权限，只在停服务窗口存在；不使用业务账号提升权限，不部署通用 bypass HTTP 接口。bootstrap 同一 username 已存在即拒绝，不复用或升级未知账号；RoleCode/tenant=NULL固定，口令从交互隐藏输入/受限fd读取，不放 CLI args。
- 私有存储目录不可经静态服务器/代理直接访问；只通过授权 API；上传限额/代理限额相容；真实 PDF 访问、撤销/过期、账号失效、跨校/专家原文负例都有实际证据。

## T10-B 恢复与回滚

数据库+文件必须来自同一停写窗口；写入暂停包括 worker/定时任务/外部上传。加密离线备份、清单 hash、角色/owner/ACL/RLS、应用构建版本与迁移版本同时留存。先在隔离恢复环境演练，禁止首次在生产做实验。

使用环境约定的全库恢复到独立实例/数据库，按实际 schema/角色/路径恢复；如 storage_root 必须变化，停应用后仅对受控 file_objects.storage_key 做严格源前缀→目标前缀转换，逐文件验证，不篡改 dump SQL；恢复失败不切流量。实际环境不受本地测试5433限制，但必须另有明确部署/恢复授权，不能由执行包推断。

恢复后先轮换 JWT_SECRET、撤销全部 refresh 会话，再开放登录，防止备份之后的撤销被回滚；旧 access/refresh/download token 均拒绝。不能承诺保留停写点之后的数据；用实际丢失窗口和耗时核对用户确认的RPO/RTO，不达标则不放行。迁移失败优先事务回滚/前向修复；需要版本回退时使用对应旧构建+配套DB/文件包，不强行运行有数据时被禁止的 Alembic downgrade。

## T11-B 放行

环境实测通过 T09-B/T10-B；Hosted CI 或约定的替代检查有可核对记录；T11-A关键主链在目标环境使用授权虚构样本复验。检查账号发放、值守/故障联系人、回滚演练、正式数据权限和停止试点条件。所有阻断清零并取得用户最终部署/试点授权才可切流量/导入正式数据。

发布记录列版本/迁移、时间、操作者、备份编号、验证、未解决低风险事项、回滚阈值与负责人。实际域名、通知方式、保留期等事实必须来源于输入；不要替用户编造。
