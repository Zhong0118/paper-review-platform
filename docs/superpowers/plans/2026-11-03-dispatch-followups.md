# 后续派单：交付顺序

1. 11 无可派候选：复用平台候选请求、既有可操作标记与后端给出的全部排除原因。先用已有真实模式组件测试覆盖空集、多原因、可用零分、加载失败/过期响应，再实现并运行真实模式构建。浏览器用受限平台账号核验，其他角色沿用现有后端拒绝契约。
2. 15 接单与评阅期限：两者分别设计、配置和验收；明确学校批次生效时点，旧任务不猜测回填。未确定学校期限口径前不添加默认天数。
3. 18 专家负荷：邀请和已接单分开显示；是否改变派单资格由用户决定。数据由平台可见的真实任务产生，不将前端占位值用作业务数值。
4. 16 延期申请依赖 15：须先确定可申请时段、谁批准、次数。保留原期限、修改记录、审计；验证审批与任务终结的并发及角色可见性。

每项先更新具体设计、红灯、实现和定向复验，再更新交接。业务规则以用户确认结果为准。
