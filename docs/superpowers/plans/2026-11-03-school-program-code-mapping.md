# 20 校内专业代码映射执行计划
依据：[已批准设计](../specs/2026-11-03-school-program-code-mapping-design.md)。本轮只做 20。以下门槛在写业务代码前确定。
1. 数据与隔离：0028 追加不可变的学校年度目录版本、批次一次性绑定及独立的论文版本选项表。目录含校码、校名、官方类别、启停及校方来源。用复合外键限制学校归属，强制 RLS；专家能读匿名论文时仍不能读校码表。空库升级、回退、含数据拒绝破坏性回退；同步恢复演练清点数量。
2. 导入：学校界面下载 UTF-8 CSV 模板，指定年份及校方来源版本和出处，预览逐行新增/变更/错误；空值、重复、未知官方类别整批拒绝；遗漏行继承，停用需显式填写。确认重算基于内容、学校、操作者与上版的指纹，学校/年度锁下新建版本。无正式表时不建立默认校码。
3. 批次：在批次管理显式选本校已发布版本；未绑定的 DRAFT/OPEN 批次可首次绑定，使用与建稿相同的批次行锁，绑定后不替换。未绑定仍走官方单选。
4. 草稿：学生按新建资格或本人论文原批次获取选项，能搜两套代码/名称。提交版本号和校码；服务端解析官方类别，拒绝伪造、跨校、跨版本、关闭学科。旧草稿不强迫选择，主动换专业才走新映射；撤回/退回复制版本时保留原选项。学校/本人显示双口径，专家、推荐和匿名导出继续使用原来的公开字段。
5. 先红后绿：测试导入、不同学校同码、并发过期、绑定不可替换、前导零、历史兼容、专业门禁、角色投影、迁移/恢复。实际启动真实 API/Vite/Chrome，以虚构校方表试走导入、绑定、搜索、建稿、刷新、学校查看和拒绝路径；保留可核验证据。所有数据库操作限本机 5433/paper_review_test 临时 schema。无发布、无生产数据。

执行结果见[20 实测与复验记录](../../reviews/2026-11-03-school-programs-validation.md)。导入、绑定、学生选择、学生撤回复制、专家匿名性及隔离恢复已验证；原验收发现学校人工退回被旧版本表写权限阻断；下列批准的补修已通过复验。

### 人工退回补修（用户已批准）

1. 复现受限学校账号退回时的 42501，并保存原失败断言。
2. 新增独立迁移 0029。在既有工作流持有论文行锁时，先写同事务的退回事件，数据库仅在该论文从 PREPARING 到 DRAFT 时，从冻结版本复制字段、原文件关联和已有校码。业务账号不获通用版本或文件写权限，不修改旧版本，不锁专家任务。
3. 验证跨校、无事件、过期事件、直接写、陈旧请求、整体回滚；重新执行 20 专项、迁移/恢复和真实浏览器退回→学生重新打开。11、15、18、16 继续暂缓。
