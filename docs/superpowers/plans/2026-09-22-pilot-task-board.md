## 状态与优先级

“可执行”表示任务边界已经足够明确；“依赖后执行”需先通过前项；“待定规格”只可调查/细化，不可直接编写业务实现。已有 18 项修复完成率不沿用为本表的完成率。

| ID | 任务/交付 | 状态与依赖 | 建议执行者 | 可核验出口 |
|---|---|---|---|---|
| T01 | 工作树交接与基线复验 | 可执行 | Sol | 确认修复快照完整；前后端测试、类型、真实构建及迁移测试可复现；交接记录 |
| T02 | 一致的本地检查命令与 CI 文件 | T01 后执行 | Sol；Astra 审查 | 同一脚本用于本地/CI；任何检查失败整体非零；不触碰开发库；远端未运行须标记 |
| T03 | 可复现隔离验收环境与多角色矩阵 | T01、T02 后执行 | Sol；复杂失败交 Astra | 不依赖 /tmp 旧脚本或手改数据库，能启动虚构场景并清理；实际观察和未测项分开 |
| T04 | 固定首批试点范围 | 待用户业务信息；可提前收集 | Astra + 用户 | 明确学校/账号规模、评审人数/评分规则、部署、SSO/代传/收费是否必需；得到可追踪决定 |
| T05 | 账号、角色、资格与批次的最小运营规格 | T04 后定规格 | Astra 设计；Sol 执行已批准小片 | 非开发人员能建立下批业务；不依赖编辑 seed；停用和越权有负向验收 |
| T06 | 数据隔离设计与 RLS 实施 | T04/T05 的身份及数据边界确认后定规格 | Astra 主导 | 普通运行账号不得绕过 RLS；两租户、专家跨校、平台角色、连接池上下文与后台作业均有隔离测试 |
| T07 | 专家资料、状态与回避维护 | T05 后定规格 | Sol；Astra 审查规则 | 修改后影响新指派；历史结果不漂移；停用/回避目标不能通过直接 API 派单 |
| T08 | 试点评审规则持久化/快照 | T04 后定规格；T05 提供批次入口 | Astra 设计；Sol 执行外围 | 人数/模板/汇总版本在轮次固定；不支持的配置明确拒绝；单专家约束不被意外放开 |
| T09 | 生产配置、认证与私有文件部署 | T04 部署选择、T06 隔离方案后定规格 | Astra 审查；Sol 执行脚本 | 无默认生产密钥/种子密码；TLS、文件访问、日志敏感信息与配置失败策略验证 |
| T10 | 数据库与文件一致恢复、迁移回滚 | T09 后定规格 | Sol 演练；Astra 审查 | 从备份恢复后论文和文件关系有效；失败升级可恢复；恢复时间/数据损失目标由 T04 确认 |
| T11 | 试点发布演练与放行记录 | T03/T05–T10 及所有试点必需项通过 | Astra + 用户 | 多角色主链/异常路径、权限、容量与浏览器矩阵有证据；阻断项清零；用户确认实际部署 |

T05–T10 不是已批准接口设计。每项开始前必须生成一个具体切片（文件、接口、权限、状态、测试、回滚），再拆为可独立验收的小任务。T06/T09 安全门禁不能因时间不足省略。

多专家、财务、通知、SSO、批量导入不默认插入近期实现。如果 T04 确认某项是试点必需，先重排依赖及验收出口，不能直接照此表上线。

## 换 agent 的执行约定

- 当前先交 Sol T01，再用 T02/T03 检查其独立交付和返工情况；不保证模型切换必然降低总成本。
- Astra 负责涉及隔离/权限/并发/规则的数据设计与审查。普通页面、明确接口、脚本由 Sol 执行。
- 发现需求冲突、需要改变公开接口/权限/状态模型、同一问题两次修复未通过时，记录最小复现和失败原因，转 Astra 诊断；不得通过删断言或放宽权限“完成”。
- 每项交付：实际改动、测试命令/结果、未覆盖项、工作树状态、下一项。不要复制整个历史对话；读入口文档和本任务相关代码即可。
- 本表只是计划。初始所有任务未完成；更新状态必须附结果位置。
