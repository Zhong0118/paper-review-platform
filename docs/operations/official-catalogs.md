# 官方目录维护

本次采用教育部2026-06-17全国高校名单：普通2952所、成人244所；研究生采用2022目录的一级学科与专业学位类别184条。全国名单不含港澳台；不代表各校具有对应学科授权或已入驻本系统。学校自己的学院/培养专业/研究方向不由国家目录推测。

原件、规范CSV、下载链接和SHA256在 `backend/data/official/manifest.json`。研究生PDF来自中国政府网原件镜像；高校XLS来自教育部附件服务器，附件链接经教育部中国大学生在线发布页核对。现有前端184项代码/名称已逐项比对，无差异。

## 使用

1. 系统管理员 → 学校管理 → 官方基础目录 → 预览 → 核对新增/变更/来源 → 确认导入。导入只修改目录；不创建任何账号/学校，不删除未出现的条目。过期预览409后重新预览，不能自动重放。
2. 新增学校时查询官方院校，选择后建立租户/组织和首位审核员。内部租户ID仍为UUID，官方10位学校标识码单独关联；旧租户与旧API保留人工字段兼容，不自动猜测对应学校。
3. 学校审核员 → 本校送审学科，勾选可用范围并保存。未配置明确沿用全局启用学科，保存空集合表示没有新可选项。历史论文仍显示原代码/名称，未改学科可以保存旧稿；再次提交必须满足当前开放范围。
4. 学生新建论文必须先选择学科，不再默认计算机；专家选可评学科使用可搜索多选。目录失败显示错误，不回退演示列表。

## CSV/Excel受控转换

仓库根运行（不连接数据库）：

```sh
PYTHONPATH=backend backend/.venv/bin/python -m scripts.verify_catalog_source backend/data/official/institutions-regular-2026.xls --kind REGULAR
```

支持 `.csv` / `.xls` / `.xlsx`，XLS/XLSX须采用教育部原表结构；CSV须使用仓库同名CSV表头，代码必须文本保留前导零。可用 `--output /明确路径/new.csv` 输出规范CSV，仅创建新文件，不覆盖。转换结果必须与已审核官方快照完全一致，来源不明、缺行/重复/改名的文件拒绝。

当前Web导入的是内置已核验快照，不提供任意文件上传或任意URL抓取。更新到新的官方版本时需下载原件、更新规范数据与manifest，经差异审核/测试后随版本交付；业务运行不依赖外网可用性，不在业务代码手工新增条目。用户自建专业映射需要学校提供材料，本次没有编造。

## 验收边界

新增迁移0020只在独立测试schema运行。本次不迁移开发库或生产库；因此打开未经迁移的旧服务不会自动获得新表和官方数据。真实环境迁移、初次目录导入仍需部署流程。恢复/RLS检查增加两张表（共30张业务表）。

## 学校自己的专业代码（目录 0028；人工退回 0029）

全国目录提供官方代码，学校自己的代码和名称以该校正式培养或招生目录为准。没有校方认可的映射表时，批次保持未绑定，学生仍可选择已开放的官方学科。

1. 学校审核员打开「本校送审学科」的「校内专业目录」，下载 UTF-8 CSV 表头。四列依次为 `校内代码,校内名称,官方代码,状态`。把两列代码都当作文本，保留前导零；状态填「启用」或「停用」。每个年度同一个校码仅有一个官方类别；同年跨学院重码应先由学校确认，不自行推断。
2. 填目录年度、校方正式文件名或官方链接、来源版本。点「预览校内目录」核对新增、变更与错误。发现重复或未知官方代码，修正后重新上传；未列出的旧行会保留。如果有人先发布了同年度新版，需要重新预览。
3. 确认发布后，到「批次管理」→「设置校内目录」，核对年份、目录版号和校方来源版本后确认。草稿或开放批次均可首次绑定；**绑定后不能换版**。更正映射时发布新目录供后续批次使用，旧批次继续使用当时的版本。
4. 学生新建论文时按校码、校内名称、官方代码或官方名称搜索。学校和本人看两套口径，专家派单继续按官方学科。绑定前已建的旧稿无需重填；主动换专业时才选校码。停用项和学校未开放的官方类别不会成为新选项。

学校因材料问题退回时须填写原因。学生重新打开草稿，可以修改内容，不必重新选择专业或上传原有文件。部署该版本前应按既有流程迁移到 0029；如果提示“退回版本未生成”，先核对迁移，不要手工改论文状态。
