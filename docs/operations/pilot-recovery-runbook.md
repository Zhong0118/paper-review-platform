# 本地试点恢复演练运行说明

此说明只适用于 `paper_review_test` 的**新建虚构数据**。脚本不接受已有 schema 或目录作为恢复目标；现有数据库容器仅提供版本匹配的客户端。实际部署、旧应用构建回退、异地备份、RPO/RTO 和正式账号处置属于 T10-B，不能把本地演练当作生产恢复步骤。

## 运行

从仓库根目录执行：

```sh
PYTHONPATH=backend backend/.venv/bin/python -m scripts.recovery_drill
```

前提是本机 `127.0.0.1:5433` 的 `paper_review_test` 可连接，现有 `paper-review-postgres` 容器运行且映射 `127.0.0.1:5433 → 5432/tcp`。脚本先核对目标库、容器ID/镜像/端口和 `pg_dump`、`pg_restore` 相对服务端的主版本；不会重试安装客户端、迁移开发库或停止其他进程。

脚本新建隔离 schema、三种普通登录和临时存储，准备一篇已发布的虚构论文与原文/匿名 PDF。停写并释放业务/认证连接后，容器内16版 `pg_dump` 通过无TTY二进制流写入宿主机0700临时目录；数据库归档、清单和文件包均以0600创建。容器内密码只保存在本次随机0600 `PGPASSFILE`，不进入命令参数或日志；其inode核对后精确删除。

恢复前验证归档 SHA256/TOC、清单、所有文件哈希、源 schema OID、三角色身份和存储 inode；任何不符均拒绝删除。然后只删除本次登记的 schema/存储，在同名 schema 和同一绝对路径用 `pg_restore --single-transaction --exit-on-error` 重建，保留 owner、有效权限、RLS、函数和触发器。恢复后比对29张表（28张业务表加Alembic表）的行数、owner、有效GRANT与RLS、轮次规则、结果、论文/任务/发布时间及文件哈希；以普通角色API复验学生/导师结果与本人文件200、外校结果和专家原文404。脚本还演练DDL事务失败回滚及备份后虚构写入的时间点回退。

成功输出 `local_recovery=PASS`、备份/恢复秒数和 `cleanup=PASS`。失败时不启动恢复后的业务验收；若资源身份不符，外层退出路径也会拒绝清理可疑资源。不要使用通配符或对现存资源运行 reset/clean；先用报错中的本次资源标识人工核对所有权。脚本正常结束后应只读确认其精确 schema、三角色、存储目录、归档目录和容器内临时凭据均不存在。

恢复点是备份时间点：备份后撤销的 access/refresh 会话可能随数据库回退。实际环境恢复必须按 T10-B 停服、轮换 JWT 密钥、撤销 refresh 会话并重新登录验收；本地演练不会改开发环境密钥或承诺跨恢复撤销。旧应用构建兼容性及真正的恢复时间/数据损失目标尚未验证。
